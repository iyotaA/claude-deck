# 画面側

> `public/` 配下（`js/` と `css/`）を触るときに読む。
> 全体の地図と横断の約束はルートの `CLAUDE.md` にある。

バニラ JS。フレームワークもビルドも無い。`index.html` が読む `<script>` は1本だけ。

```html
<script type="module" src="js/main.js"></script>
```

ESM なので**読み込み順を人が守る必要はない。** import が解決の順を決める。
素の `<script>` を2本並べていた頃は、順番を入れ替えると立ち上がらず、
トップレベルに同じ名前を2つ置くと SyntaxError で丸ごと落ちていた。その危険は無くなっている。

拡張子は `.js` のままにする。`.mjs` を `public/` に置くと `server.mjs` の `MIME` に無く、
`octet-stream` で返るのでブラウザが module として読まない。

`public/js/` の下に平置き ＋ `timeline/` の1フォルダ。**import は上から下へ一方向にだけ流す。**

**枚数はここに書かない。** 前は「31枚」「33枚」と書いていて、どちらも実態とずれていた
（数える記述はファイルを1枚足すたびに腐る）。下の表が全部を並べているので、
数が知りたければそれを数える。**これは CSS の表にも効く**（あちらも「16枚」で腐っていた）。
逆向きに import したくなったら、置き場所が間違っている。

数値は**取り口を3つに分けてある**（`session.js` の中）。
詳細（2秒ごと）・数値（15秒あけて取り直す）・中央値（5分あけて取り直す）。
同じ `loadDetail()` から並べて撃ち、着いた順に画面へ出す。
詳細の到着を待たない。待つと、キャッシュが効いた詳細のときだけ数値が遅れて出ることになる。

**どれも「選んでいるセッションのものか」を id で突き合わせてから出す。**
選び直した直後は前のセッションの数値が store に残っているので、
突き合わせないと**他人の数字**を数秒のあいだ出し続けることになる。

層3 の中の向きは1本。`detail-wait.js` → `run-ask.js`。
「あなたの番」のパネルに要求が来ているときは、待ちの中身も操作もあちらが持つので、
`waitingBlock()` が丸ごと早期 return する。**逆向きに import しない**（`run-ask.js` は
`WAIT_GUIDE` を知らなくてよい）。`run-view.js` とは向きを作らず、`RUN_OVER` をあえて重複させている
（`run-resume.js` と同じ線）。

層7 の中の向きは3本。`palette.js` → `run-form.js` ／ `palette.js` → `mode.js` ／ `palette.js` → `today.js`。
どちらも片方向で、逆を足すと循環になる。
（ここには長く「`stream.js` → `mode.js`」も並べてあったが、その import は存在しない。
`mode.js` を見ているのは `palette.js` と `main.js` の2つだけ）
`usage-tab.js` と `archive.js` は誰からも import されない（呼ぶのは `main.js` だけ）。
書庫と数値を出す口は `initMode({ onArchive, onUsage })` で外から差す。
`mode.js` があちらを直に import すると、同じ層の中に向きが1本増える。
`palette.js` は層7 のいちばん下流で、誰からも import されない（呼ぶのは `main.js` だけ）。

`archive.js` が層7 なのは `session.js`（層5）を見ているため。

**カードは `list.js` から借りていない。** ここには長く「`buildCard` を借りている」と
書いてあったが、実際には `archive.js` が独自に組んでいた。3つ（一覧・書庫・数値）を
並べて分かったのは、借りられなかった理由のほう ―― 上段に出すもの・札・押したあとが
**問いごとに違う**（状態／日時と大きさ／消費）。
いまは定型だけを `card.js`（層2）に置いて、「何を出すか」は各自が持つ。
カードを使うのは書庫と数値の2つだけ。稼働中の一覧は圧縮した行（`.row`）に替わったので、
誰からも呼ばれなくなった `list.js` の `buildCard` は消した。

`timeline/` の中も同じで、`kinds` `waits` → `search` → `blocks` → `item` → `view` → `index` の順。
**`timeline/` の中のファイルを、外から直に import しない。** 呼びたくなったら `index.js` の口に足すか、
そもそも時系列の仕事かを考え直す。

例外は `kinds.js` で、**3箇所が直に見ている。**
`store.js` は循環を切るため（`index` → `view` → `store` になる）。
`detail-panels.js` は `splitEdits` を使うためで、あれは `index.js` の口に無い
（時系列の語彙だが、パネル側でも同じ分け方が要る）。
`about.js` は凡例を `KIND_MARK` ＋ `MARK_GROUPS` ＋ `KIND_LABELS` から組むため
（**印の意味を画面側に書き写さない**ので、語彙そのものを見に行く必要がある）。

3つとも**層0 のファイルを見るだけ**なので、import の向きは崩れていない。

**循環を切っている所が4つある。動かすと立ち上がらない。**

| 切り方 | 切っている循環 |
|---|---|
| `hideQueryValue` は隠す種類を引数で受け取る | `store` → `kinds` → `store` |
| `store.js` は `timeline/kinds.js` を直に見る（`index.js` を経由しない） | `index` → `view` → `store` |
| `detailErrorNow` は `rows.js` に置く | `detail` ⇄ `session` |
| `setListOpen` は `drawer.js` に置く | `list` → `main` → `list` |
| 拡大は `zoom.js`（層2）に置き、組み直しは `initZoom({ onChange })` で差す。「次の待ち」の選び直しも `onPick` で差す（`session.js` は層5） | `detail` ⇄ `zoom` |

実行の台帳も同じ形で切ってある。**`runs.js`（層2）は描画側を知らない。**
`subscribeRuns(fn)` で外から登録し、配線するのは `main.js`（層8）。
`runs.js` が `run-view.js` を import すると `runs`(2) ⇄ `run-view`(3) の循環になる。

配るのは**台帳が動いたときだけ。** 現れた・状態が変わった・終わった・許可を訊かれた
（または答えた）・設定を替えた、と枠の使用率が動いたとき → `renderDetailIfNeeded()`。

**速報（`run` の出来事）は1件も配らない。** 画面が1件も持たないから配る中身が無い。
1ターンで数百行来るので、そこで作り直すと開いた `<details>` と入力中の caret が毎回消える。
`detailKeyOf()` に混ぜるのも `runStampFor()`（**出来事が増えただけでは動かない値**）だけ。

**それでも `run` の受け口は残してある。** `takeSeq()` が seq の水位を進めるためで、
つなぎ直しの起点（`/api/runs/stream?from=<seq>`）がこの数そのものになる。
受け口ごと消すと起点が 0 に戻り、切れるたびにリング1000件を送り直させる。

ふるまいで気をつけている所。

- SSE でつなぎ、`apply()` が一覧・まとめを描き直す。詳細は `renderDetailIfNeeded()` を通し、`detailKeyOf()` の値が動いたときだけ作り直す（毎回作り直すと開いた `<details>` と入力中の caret が消える）
- 時系列だけは `Timeline.render()` が `.tl-host` を差し替える。絞り込みの帯は器の外に置く（中に入れると1文字ごとに入力欄が作り直される）
- 描く先は `Timeline.attach()` で預け、`Timeline.detach()` で外す。外から時系列の内部状態を触らない
- 詳細は `detailCache`（`logSize` を印にした8件のキャッシュ）。中身が変わっていなければ取り直さない。印が `0`（不明）なら必ず取り直す
- 取り直しのあいだは `silent` で前の内容を出したままにする
- 作業台の左右の幅は、列の境目のつまみ（`.splitter`）をドラッグして変える。**動かしているあいだ `resize.js` が書くのは生の px 1つだけで、上下限は `base.css` の `clamp()` が持つ。** 窓が狭いときの蓋（`min(…, 40vw)`）も CSS 側なので、窓をリサイズすればその場で効き直す
- 覚えるのは**`clamp()` を通ったあとの幅**（`getBoundingClientRect().width`）。1回のドラッグにつき1回だけ書く。既定へ戻すのは値ではなく削除（インラインの変数と `localStorage` の両方を消す）で、行き先は `base.css` の `:root` に任せる
- つまみは矢印キーでも動く（1回 16px・Shift で4倍）。`Home` と二度押しで既定へ戻る。焦点が見えないと矢印で動くことに気づけないので `:focus-visible` で塗る
- 一覧は**畳める列**。畳むと grid の列が 0 になり、幅が中央へ渡る。閉じているあいだは `inert` で丸ごと触れなくする（幅 0 でも中身は DOM に残るため）
- 狭い画面（860px 以下）だけは**手前に重なる引き出し**（`position: fixed`）。畳んでも中央に渡せる幅が無く、開けば中央が潰れるため。膜もこちらだけ
- **「選んだら閉じる」は重なっているときだけ**（`closeListAfterPick()`）。列のときに畳むと、開けておいた意味が無くなる
- 狭い画面（860px 以下）では右インスペクタが下から出る紙（ボトムシート）になる。**`position: fixed` で浮かせず、grid の同じセルに重ねる。** 幅は列が決めるので二重に書かずに済み、引き出し（`z-index: 40`）と膜（`30`）の階層にも手を出さない
- 画面のモードは `MODES`（`work` / `archive` / `usage`）で照合する。三項演算子で二値に畳まない。`localStorage` には残さない（書庫を開いたまま保存すると、次に開いたとき「誰が待っているか」が見えない状態で始まる）。固定したい人は `?mode=archive` `?mode=usage` でブックマークする
- **数値がタブではなくモードなのは、出す中身がセッション1本のものではないから。** 左のペインは「どのセッションを選ぶか」の場所なので、そこに横断の集計を置くと、選ぶための場所に、選んでいるものと関係のない数字が出ることになる。0.3.0 で配った `?tab=usage` は `initialMode()` が `usage` へ読み替える（**配ったブックマークは切らない**）
- **作業台でないあいだ `apply()` は何も描かない**（`store.mode !== 'work'` で早期 return）。中央も左も消えているうえ、書庫（`/api/archive`）も数値（`/api/usage`）もファイルを開く窓口なので、見えないもののために毎2秒撃たない。作業台へ戻るときに `setMode('work')` が3つとも追いつかせる（**「左の一覧に触るとスクロール位置が毎秒先頭へ飛ぶ」も理由に挙げていたが、そちらは `listKey()` で消えた。** それでも早期 return は残す ―― 理由の本体は「見えない窓口を毎2秒撃たない」のほう）
- URL クエリで開き方を指定できる … `?session=<id>` `?only=1` `?nolive=1` `?mode=archive|usage` `?aq=` `?asort=` `?aproj=` `?adays=` `?tq=` `?hide=`
- **`?theme=` はもう読まない。** 明るいテーマがあった頃に配色を固定するのに使っていたもので、前の版のブックマークに付いていても受けて無視する（画面は暗いまま開く）。断りも書き換えもしない
- **配ったブックマークを切らない。** `initialMode()` が古い形を3つ拾う。`?tab=usage`（0.3.0）→ 数値、`?tab=archive`（0.9.1 まで）→ 書庫、`?mode=board`（監視盤）→ **作業台**。監視盤を書庫へ送らないのは、あれが「どれから手をつけるか」の画面で、その役目を引き継いだのが左の一覧の状態の見出しだから。書庫（過去を探す）は問いがまるごと違う。書き戻す側（`syncQuery`）はもう `?tab=` を出さない
- 数値のパネルは、詳細（`d`）が読めていなくても出す。別の窓口から届くので、詳細の失敗に巻き込む理由が無い
- **数値と中央値は `detailKeyOf()` の材料に入れる。** 入れないと、遅れて着いても鍵が動かず画面に出ない。中央値は有無だけでは足りず（5分ごとの引き直しで中身が動いても鍵が同じになる）、オブジェクトそのものも比べられない（毎回別の参照で届く）。実際に出している値だけを1本の文字列にして混ぜる
- 窓口ごと無いと分かったら一度で諦める（更新の前後で、画面だけ新しくサーバーが古いことがある）。404 の切り分けは**理由が JSON で返るかどうか**。返るならセッションが無いだけ、返らないなら窓口ごと無い
- **中央値が取れなくても何も言わない。** 差は添え物で、無くても数値は読める。ここでエラーを出すと、数値パネルの主役（何が文脈を食っているか）から目が逸れる
- `?hide=` は「キーが無い」と「空で付いている」を分けて見る。空は「何も隠さない」の指定なので既定に戻さない
- 隠している種類だけは `localStorage` に覚えさせない。開き直したら既定（足跡を隠す）に戻す。覚えさせると、足跡をいちど押して中を見ただけで既定が永久に壊れる
- 種類を隠すときは、その種類だけを数えた省略の目印（`elided`）も一緒に落とす。残すと「20 件を省略しました　足跡 20」の文字だけが並び、隠れていないように見える（実測で窓 120 件のうち 36 件がこれだった）
- **省略は絞り込みのチップに出さない。** 上の通り、出るか出ないかは他のチップ側で決まるので、独立したチップにすると件数が嘘になる。実測では「省略 74」と出しながら1行も出ない状態になっていた（74 件すべてが足跡だけの区間で、足跡は既定で隠れる）。その状態で他を全部隠すと時系列が空になる。目印ごと消す指定は URL に残してある（`?hide=elided`）
- 窓（`TL_FIRST` = 4 で開き、`TL_MORE` = 60 ずつ継ぎ足す）の外にしか無い種類は名前で伝える。足跡は新しい 200 件だけが残るので、古い順で見ていると窓の中に1件も入らないことがある。黙っていると「押しても変わらない」に見える
- 描画にかかった時間は `window.deckPerf()` で見る（目安は `renderDetail` が 50ms 未満、時系列の描き直しが 16ms 未満）。測る入れ物は `perf.js` の1つに保つ（2つに割ると `deckPerf()` が片方しか見えない）
- **16ms の目安が当てはまるのは普通の描き直しまで。** 「続きを出す」で 60件を一気に継ぎ足す回と、絞り込みの語を変える回は元から 17〜35ms かかっている（実測。Markdown 化の前後どちらでも同じ）。ここを直すなら窓の刻みか描き直しの範囲の話で、**測ったあとに「前より遅くなった」と読み替えない**。比べるときは同じセッション・同じ件数・同じ操作で前後を測る
- パレット（Ctrl+K）は**自分では何も決めない。** すでにある窓口（`select` / `setDetailTab` / `setInspector` / `setListOpen` / `openRunForm` / `focusTerminal`）を呼ぶだけの器にしてある。判定を持たせると、画面の押しボタンとパレットで挙動が食い違う
- 設定モーダルは `<dialog>` ＋ `showModal()`。Esc・背面の膜・焦点の閉じ込めがタダで付く。中身は**開いたときに1回だけ**引く。ここを毎秒更新しない
- **モーダルの高さは固定する（`height`。`max-height` にしない）。** 節ごとに中身の量が違うので、中身なりにすると切り替えるたびに伸び縮みし、`<dialog>` の中央配置で上下に跳ねる（実測で 354〜535px・上端が 91px ずれた）。値はいちばん中身の多い通知の節が収まるところに置く
- 設定モーダルの中身は4つ（通知・作業フォルダ・起こすときの既定・いまの様子）で、**引く窓口も分かれている。** 1つが転んでも他は出る（`load()` / `loadDirs()` / `loadRunDefaults()` / `loadStartup()` をそれぞれ投げっぱなしにする）
- **「起こすときの既定」は選択肢を書き写さない。** 語彙・候補・範囲は `/api/runs/options`（起こすフォームと同じ窓口）から引く。2箇所から配ると、語を1つ足した日に片方だけ古くなる。あちらから貰う形にもしない … `settings.js` → `run-form.js` の向きができて、同じ層7 の中に辺が増える
- **既定の欄は触った瞬間に保存する**（作業フォルダと同じ経路。足の「保存」は通知の節にしか出ない）。送るのは触った項目だけで、空文字が「消す」の意味になる。**「自分で入力」へ移した直後は保存しない** … 送ると、書こうとしている最中に「指定なし」で上書きされる
- **その3つを1枚に積まない。左で節を選び、右に中身を出す。** 前は9つのかたまりが縦一列で、その中に「保存を押すまで効かないもの」「押した瞬間に効くもの」「そもそも変えられないもの」が同じ顔で混ざっていた。節を分けると、足のボタンを**いま開いている節に効くものだけ**に絞れる
- **節の出し入れは CSS がやる**（`.settings[data-sec]` で絞る）。`settings.js` は `dataset.sec` に名前を書き、押した札の `aria-pressed` を付け替え、足の1行（`SEC_NOTE`）を入れ替えるだけ。JS で出し入れすると、節を1つ足すたびに配線が増える
- **作業フォルダだけ保存の経路が違う。** 足す・消すはその場で効く（`/api/settings/rundirs`）ので、足の「保存」ボタンは通知のぶんだけを送る。**その節では保存のボタンごと出さない**（`settings.css` が `:not([data-sec="notify"])` で隠す）。前は本文の説明文で「その場で保存されます」と打ち消していたが、**形で伝わっていないから文で補うことになっていた**
- **通知の送り先は2つ（Slack と Windows の通知）。** 通知の節のいちばん上に「通知先」の段を置き、Windows の通知の入り切りを出す（見た目は「鳴らす状態」の `.settings-states` を借りる）。**選んだ値（`toast`）と実際に出せるか（`toastEnabled` / `toastReason`）を分けて見る** … 入れていても止めるスイッチや Windows 以外では出せないので、そのときは添え書きに理由を出す。足の1行は「Slack 有効・Windows 有効 / 送信 N / 失敗 N」、いまの様子は送り先ごとに1行（`.settings-hint.is-lines`）
- **鳴らない理由は足に書かない。** 足の1行は通知の節でしか出ないので、そこだけに置くと他の節から辿り着けない。足には短く（`有効 / 送信 12 / 失敗 0`）、理由は「いまの様子」の節（`#settings-health`）に置く
- **読むだけの節は面を沈めて枠を外す**（`.settings-read`）。押せるものが1つも無いことを、文ではなく面で示す（「押せないものに枠と面を持たせない。押せない札は字だけ」の線と同じ）
- **追加欄の Enter は保存ではなく「足す」へ回す。** 見た目を `.settings-text` から借りているのでクラスでは見分けられない。参照（`ev.target === dom.runDirAdd`）で分ける（`run-form.js` が本文欄を分けているのと同じ作法）
- モーダルを `<form>` で囲まない。囲うと入力欄で Enter を押した瞬間に閉じる（保存したつもりで消える）。Enter → 保存は `settings.js` が自分で拾う
- URL の入力欄は常に空で開き、いまの値はマスクして `placeholder` に出す。`****` のような偽の値を `value` に置くと、それをそのまま保存して URL を壊す。空欄＝「変えない」、消すのは「消す」ボタンだけの役目
- 数値の欄も空ならキーごと送らない。サーバー側が「キーが無い＝触らない」なので、そこに乗る
- `.settings` に `padding` を持たせない。持たせるとその余白を押したのが背面を押したのと区別できず、`ev.target === dialog` での判定が崩れる
- 更新の帯は、押したあとの見張りを画面側が持つ。当てる作業はサーバの外（C# の別プロセス）で走り、しかも途中でサーバ自身が落ちて起き直る。「押したのに何も起きない」を捕まえられるのは画面側しかないので、無音で終わらせず `STUCK_MS`（120秒。`server.mjs` の `APPLY_GUARD_MS` と同じ）で必ず時間切れを出す
- **更新の道中は覆い（`<dialog id="updov">`）で見せる。** 前は帯に動かない文字が出るだけで、止まっているのか進んでいるのか見分けが付かなかった（実測の指摘）。覆いには回る輪・段の並び（準備 → 取り寄せ → 入れ替え・起き直し）・経過時間を出す。入れ替えのあいだはサーバーが止まっていて何を押しても効かないので、覆ってしまうほうが正直。Esc と「裏で続ける」で畳むと、同じ中身が帯へ移る（回る輪・経過時間・段の並びつき。道中は「閉じる」を出さない）。**動きを減らす設定でも輪だけはゆっくり回す**（2.4秒で1周）… Windows の「アニメーション効果」をオフにしているだけでブラウザは reduce を名乗り、輪が止まって「進んでいるか分からない」が直っていなかった（実測）。`base.css` の `!important` を `!important` ＋ 詳細度で上書きする。流れる線と「更新中」の点滅は飾りなので止める
- **覆いを出し、終わったら読み込み直すのは「追いかけている窓」だけ**（`following`）。押した窓と、開いた時点で既に道中だった窓が立てる。**立っていない窓で `done` を見ても読み込み直さない** … 読み込み直した先でも `done` の紙は10分残るので、ここで止めないと読み込みが止まらない。読み込み直す前に `rememberShown()` で `done` の鍵を覚えるので、戻ってきて同じ帯も出ない。**置き去りの紙は拾わない**（`adopt`）… ランチャが道中で落ちると `downloading` / `applying` のまま残るので、見張りの時間切れ（600秒 / 120秒）より古い紙では追いかけない。拾わない窓の帯には回る輪も経過時間も付けず、閉じる口も残す
- **取り寄せの進み方が紙にあれば、覆いの輪を％で埋める**（`fillRing`。`.updov-ring[data-pct]` の conic-gradient）。段の「取り寄せ」にも `60% ・ 0:11` と添える。無ければ（古いランチャ）輪を回すだけ。輪も段と同じく**節点を作り直さない**。％は `--upd-pct` で渡す（JS が書く変数なので `test/screen.test.mjs` の `FROM_JS` に並べてある）
- **入れ替わったら5秒数えてから自分で読み込み直す**（`RELOAD_SECONDS`）。帯のときは人に押させているが、覆いは「この窓で押して見届けている」場面なので押す手間を省く。「あとで」で畳めば数えるのをやめて帯（読み込み直す）に移る。数え始めで時計（`ticker`）を回し直す ―― 揃えないと最初の1秒が前の拍の残りぶん縮む（実測 0.5 秒）。**数え終わったら時計を止めてから読み込み直す** … 止めないと、再起動直後のサーバーが遅いとき次の拍でもう一度 reload が走る
- **入れ替え中の問い合わせの失敗は数えて出す**（`waits`。「確認 6回目」）。サーバーが止まっているので失敗するのが正常で、黙って捨てると固まって見える。上のバーの「切断」も、入れ替えを見届けているあいだは `stream.js` の `setLive` が「更新中」へ言い換える（赤い点だと壊れたように見える）。判断は `update.js` が書く `store.updating` の1つで、**紙を直に見ない**（置き去りの紙で本当の切断まで隠すことになる）
- **見張りは、紙が始めたときから動くまで畳まない**（`watchFrom`）。失敗のあとの「もう一度」で、押した直後の紙はまだ `failed` のまま。前は1拍目でそれを「落ち着いた」と読んで見張りを畳み、そのあとランチャが書いた `downloading` も `applying` も**次の30分おきの確認まで画面に届かなかった**（実測）。同じ理由で、紙が動くまでは `bannerOf` に `unmoved` を渡して「始めています」を出す（古い `failed` をもう一度「失敗しました」と出さない）
- 開いた直後にもう1回だけ引き直す（`RECHECK_MS` = 10秒）。ランチャは窓を開けてから更新を確認するので、最初に引いた時点の紙はまだ前回の結果か、そもそも無い
- `/api/update` が 404 のとき（サーバーが古い）だけは、画面側で `outdated` を組む。それ以外の判断はサーバー側に置く

状態ラベルの日本語は画面側に持たない。
`/api/sessions` の `meta.stateLabels`（`STATE_LABELS` そのまま）から引く。
状態を1つ増やすときに直すのは `parse/state.mjs` だけで済む。

**どの状態が「答えないと1行も進まない」かも画面側に持たない。**
行の `blocking`（と表そのものは `meta.stateBlocking`）から引く。
`state === 'needs-answer' || …` の列挙を判定として画面に書くと、状態を1つ足した日に
一覧・詳細・レールの数の3箇所で食い違う（実際にそうなっていた）。

**一覧の束の表（`groups.js` の `YOURS_GROUPS` / `STATE_GROUPS`）は例外。** あれは「どの束に置くか」の割り当てで、
急ぎかどうかの判定ではない（1つの状態が2つの束に入ることはない、という別の約束の表）。
まとめた名前（「許可・質問で止まっている」「返信待ち」）はサーバーに無いので、日本語もそこに持つ。
急ぎの印を付ける側（左のレールのバッジ・詳細の待ちのパネルの見出し）は `row.blocking` / `meta.stateBlocking` を見る。

CSS は `public/css/` に平置き。`index.html` の `<link>` の並びが、そのまま重ね順になる。

**`<link>` の順番を入れ替えない。** CSS は宣言順で勝ち負けが付く。
`narrow.css` は上の全部を上書きするので、必ず最後に読む。
`ask.css` は `run.css` の直後・`markdown.css` の前。あとに置くと、
承認カードの中のプラン本文に対して `markdown.css` の見出しの寸法（実測で決めてある）を
うっかり上書きできてしまう。

`usage.css` も**色を新しく作らない。** 使うのは `--accent`（強調1本）と
`--fg-faint` / `--border-strong`（文脈）だけ。
色を置くのは `tokens.css` の1か所だけで、ここに直に書いた色は
`test/tokens.test.mjs` の比の検査（全部の面で 4.5:1 以上）をすり抜ける。
多色にすると「色は、あなたが何かすることにだけ使う」（「配色と書体」の節）も崩れる。

`settings.css` は狭い窓向けの指定を自分で持つ（`min()` と、`34rem` のグリッド畳み、`40rem` の左ナビ畳み）。
モーダルの都合を `narrow.css` に散らさないため。

**閾値が2つあるのはわざと。** 34rem は数値の3列が潰れるかどうか、
40rem は左の 9.5rem を引いた残りで長いパスが読めるかどうかで、後者が先に苦しくなる。
どちらも**窓の幅で見てよい**。このモーダルの幅は窓に付いて動く（`min(44rem, 100vw - 2rem)`）ので、
`run.css` に書いてある「器の幅と窓の幅がずれる」問題はここでは起きない。
`<dialog>` の既定は `canvas` / `canvastext` というブラウザ側の色で、意味トークンとは別系統。
`color-scheme: dark` で固定しているいまはブラウザの暗い灰色になるので白くは残らないが、
意味トークンで塗り替えないと、モーダルだけインクの地（`--bg`）から浮いた別の灰色になる。

### 段（スケール）

**単一値になっているものに段を作る。** ここが「のっぺり」の直し所そのもので、
実体は `tokens.css` の1箇所にある。

| 段 | トークン | 何が問題だったか |
|---|---|---|
| 字 | `--fs-0`〜`--fs-6`（12 / 13 / 14 / 15 / 15 / 21 / 30px） | `font-size` が 28 種類・148 箇所あるのに、**130 箇所（88%）が 10.9〜14.1px の 3.2px 幅に収まっていた**。種類は多いのに差が無い |
| 行間 | `--lh-tight`（1.5）＝ `body` の既定／`--lh-read`（1.78）＝ `.md` だけ | 詰める場所と読ませる場所が同じ尺だった |
| 影 | `--sh-1` `--sh-2` `--sh-3` ＋ `--hi` | 1段しか無く、しかも使い道はモーダル等7箇所だけ。**流れの中の面に影が1つも落ちていない** |
| 角丸 | `--r-xs` `--r-sm` `--r-md` `--r-lg` `--r-pill`（5 / 8 / 12 / 18 / 999px） | 実質 8px の1段。押せるものと読むものと器が同じ硬さ |
| 面 | `--bg` `--bg-elev` `--bg-sunk` `--bg-hi` | 3段だが明度差が小さく、階層があるのに見えない |

**字の段は px で持つ。** `rem` は**ルート（16px）基準**で、`body` の `--fs-3`（15px）とは別の尺になる。
実際そのせいで、同じ `.8rem` が「12.8px」なのか「11.2px」なのかを、
読む人が根元を辿らないと決められない状態だった。px なら書いてあるものがそのまま寸法になる。

**`.md` の中だけは `em`。** あそこは読む面（`--fs-4`）と時系列（`--fs-3`）の2つの尺で使われるので、
px にすると**どちらか片方でしか比が合わない**。

**大きい字だけを作らない。** 添え物（`--fs-0`）と主役（`--fs-6`）の両方が居ないと段にならない。

**12px を下限にする。** 和文（Yu Gothic UI）は 12px を切ると線が細くなって読みづらい。
前の段は 11 / 12 / 13 / 14 / 15 / 21 / 30px で、2026-11 の画面刷新で下の4段を1段ずつ上げた。
`public/css/` にも 12px 未満の直書き（`font-size` / `font`）を残さない。
段を通さずに書いた字は段を上げても付いてこないので、そこだけ小さいまま残る。
`--fs-0` が 12px 以上なことと直書きが無いことは `test/tokens.test.mjs` が見ている。

**`--fs-3` と `--fs-4` が同じ 15px なのはわざと。** `--fs-4` は Markdown の本文で、
上げずに 15px のまま残すことを選んだ（ユーザーの判断）。下の段が1段上がって追いついた形。
**1つに畳まない。** 役割が別（`--fs-3` は `body` と時系列の本文、`--fs-4` は読む面の本文）なので、
片方だけ動かしたくなった日にそのまま動かせるようにしておく。

**使う先の無い段を置かない。** 44px の段も引いてみたが、使う場所が1つも無かった。
残すと、次に触る人が「どこで使うのが正しいのか」を探すことになる。

**`--lh-read` を一覧へ持っていかない。** 圧縮した行が 28px から 47px へ伸び、
12本並べたときに 377px が 568px になる（＝全体が一度に見えなくなる）。
`body` は `--lh-tight`（詰めるほう）が既定で、上げるのは `.md` だけ。

#### 段の当て方（どれをどこに使うか）

| 何 | 面 | 影 | 角丸 |
|---|---|---|---|
| 押せるもの（`.btn` `.ibtn` `.drawer-close` 入力欄） | `--bg-elev` | `--sh-1` ＋ `--hi` | `--r-sm` |
| 次に押すもの（`.btn.is-lead`。1画面に1つ） | **`--accent`（塗る）** | `--sh-2` → hover `--sh-3` | `--r-sm` |
| カード・パネル | `--bg-elev` / `--bg` | `--sh-1` ＋ `--hi` | `--r-md` |
| 選んでいるもの | 変えない | `--sh-2` ＋ 光の輪 3px | 変えない |
| 急ぎのパネル（待ち・許可要求・実行。`.panel.is-hot` / `.is-warn`） | 変えない | **変えない**（光の輪も付けない） | 変えない |
| 一覧の選んでいる行（`.row[aria-current]`） | `--bg-hi` ＋ 枠 `--border-strong` | **無し**（光の輪も付けない） | 変えない |
| モーダル・拡大・下から出る紙 | `--bg` | `--sh-3` | `--r-lg` |
| 押せない札（`.stat`・レールの枠の輪） | 沈めるか持たない | **無し** | — |
| 触れたとき | `--bg-hi` | 1段上げて `translateY(-1px)` | — |

**`.btn.is-lead` だけ面を塗る。** 長く「面は塗らない」で通してきたが、それは
「状態色は点と細いバーだけ」との競合を避けるためだった。**その心配のほうが実態と合わなくなった**
―― 数えたら画面に塗った面が1つも無く（影も0箇所）、いちばん強い場所がどこにも作れていなかった。
`--accent` は状態色ではないので、「どれから手をつけるか」の読み方は動かない。
**1画面に1つだけ**が条件で、ここを増やすとまた強さの差が消える。
上のバーの「起こす」は塗らない（`.btn` のまま、絵の `plus` だけ `--accent`）。どのモードにも常に出ているボタンが
塗った面を持つと、その画面でいちばん強い場所が「いま押すべきもの」ではなく常設の道具になる。

**光の輪・薄い面・混ぜた枠は `color-mix()` で既存トークンから作る。**
混ぜて作れば、元の色を直した日に一緒に動く。新しい色トークンを足すと、
`test/tokens.test.mjs` の並び（意味トークンの一覧と、字として使うなら比の表）にも足すことになり、
色の役も1つ増える。足したのは `--bg-hi` と `--accent-soft` の2つだけで、あとは全部そこから作れる。

**焦点と選択を線の色だけで示さない。** 1px の枠を塗り替えるだけだと、
隣との差が 1px ぶんしか無い。外へ 3px の光の輪を回して面ごと持ち上げる。
**一覧の行だけは輪を付けず、面（`--bg-hi`）と枠（`--border-strong`）で持ち上げる。**
行は枠「あなたの番」（`--accent` の線）の中にも並ぶので、選んだ印までラベンダーにすると
枠と選択が同じ色で重なる（ラベンダーを減らす決め）。

### 配色と書体

**配色は Ink ダークの1種類だけ。** 地はインク（`#14121F`）、強調はラベンダー（`#CFCBFF`）。
色の値は `tokens.css` の `:root` に、意味トークン（`--bg` など）として直接書く。
画面側は意味トークンだけを使う。
`:root` に `color-scheme: dark` を置き、`index.html` の `<meta name="color-scheme">` も `dark` にしてある。
スクロールバーや `<select>` の開いた一覧のように、ブラウザが描く部品も暗い側で描かせるため。

前は明るいテーマもあり、OS の設定と上のバーの切り替えボタンで明暗を選べた。
2026-11 に廃止した（ユーザーの判断で暗いほうだけにした）。
そのとき「色の実体（`--l-*` / `--d-*`）→ 意味トークン」の2段もやめた。
2段は明暗を差し替えるための仕組みで、1種類になると目的が無くなる。

**色は「あなたが何かすること」にだけ使う。1色に役は1つ。**
1色に役を2つ持たせると、色を見ても何をすればいいかが決まらない。

| 色 | トークン | 役 |
|---|---|---|
| ラベンダー | `--accent` | 押すもの・あなたの番・選んでいる場所 |
| 赤 | `--hot` | あなたの操作で止まっている |
| 琥珀 | `--warn` | あなたの返信を待っている |

**実行中（`--calm`）は無彩色**（`#E4E2EE`）。Claude が動いているあいだ、あなたにやることは無い。
`--done`（緑。TODO の完了など、終わって通ったもの）と `--off`（終了・不明）は、あなたを呼ばない印として残してある。

**字は全部の面で 4.5:1 以上。**
字の色（`--fg` / `--fg-muted` / `--fg-faint`）と、字として使う色（`--accent` / `--hot` / `--warn` / `--calm` / `--done` / `--off`）を、
面（`--bg` / `--bg-sunk` / `--bg-elev` / `--bg-hi` / `--code-bg`）のどれに置いても割らない。
いちばん低い組は、`--hot` を触れた面（`--bg-hi`）に置いたときの 5.35:1。
`--accent` を塗った上の字（`--accent-fg`）は 12.01:1。比の数は `tokens.css` のコメントに残してある。

**数を触るときは、いちばん明るい面（`--bg-hi`）の側で確かめる。**
地（`--bg`）の上の数だけを見て「まだ余裕がある」と判断すると、触れたときの面で割れる。
前の版でも、地の上の数だけでは見えずに、沈んだ面の上で AA を割っていた色があった。
`test/tokens.test.mjs` が全部の組を計算して見張っている（落ちたら「どの字がどの面で何:1」まで出す）。

**字の3段の差は保つ。** `--fg` / `--fg-muted` / `--fg-faint` は地の上で 16.77 / 11.11 / 9.00。
添え物（`--fg-faint`）も 7:1 を超えるところまで明るくしてあるが、
段の差は残っているので「添え物は弱い」の読み方は消えていない。
`--off`（`#A09EB2`）は前の `--fg-faint` の値のまま。添え物の字だけを明るくしたので、
いまは「終了・不明」のほうが添え物より1段沈む。

**強調は明るさで地から離す。** 地（インク）と強調（ラベンダー）は同じ紫の系統にある。
前のネイビーの地に青の強調を置いていた頃は、同じ系統どうしで押せるものと地の区別が弱かった。
いまは強調を白に近いところまで明るくして、明るさの差で分けている（地の上で 12.01:1）。
強調を暗くすると、同じ問題に戻る。

**状態の点は色だけでなく形でも分ける**（`list.css` の `.state[data-s]`）。
菱形＝あなたの番／輪＝返信待ち／塗った丸＝実行中／細い輪＝終了。形なら色覚の差にも効く。
理由は「触るときに壊してはいけないこと」にある。

**面は「浮いているものほど明るい」。** 地（`--bg`）がいちばん暗く、押せるもの（`--bg-elev`）・触れたとき（`--bg-hi`）の順に明るくなる。
暗い配色でカードを暗くすると沈んで見えるため。
**`--bg-sunk` は名前に反して `--bg` より1段明るい**（前の暗いほうの割り当てを引き継いだ）。
`body` の地はこちらなので、`--bg` の床の上に置いた「沈めた」塊は浮いて見える。名前で明暗を決めつけない。

**影は暗い地に沈んで見えにくい。** だから `--hi`（内側の 1px のハイライト）で、影を落とさずに面を1段持ち上げる。

**色を置くのは `tokens.css` の1か所だけ。** 意味トークンを1つ足したら、
`test/tokens.test.mjs` の並びにも足す（字として使う色なら比の表にも）。
ほかの CSS に色を直に書かない。直に書いた色は比の検査に乗らない。

**書体は、英数字が Segoe UI、和文が Yu Gothic UI。**
`--font-sans` の先頭に `"Segoe UI Variable Text", "Segoe UI"` を置き、その後ろに前からの Yu Gothic UI 以下が続く。
Segoe UI は和文の字形を持たないので、和文の字はそこを素通りして Yu Gothic UI に落ちる。
1本の指定で、英数字と和文を別の書体にできる。`--font-mono` は変えていない。

**字は 12px が下限、本文は 15px。** 段の値と理由は「段（スケール）」の節にある。

### Markdown を描く

Claude の出力はほぼ Markdown 記法で書かれているのに、画面には素の文字で出ていた。
表が `| a | b |` のまま並び、`**` が本文に混ざる。そこを描くための2枚（`md.js` / `md-view.js`）。

**外の道具は使えない。** `marked` も `markdown-it` も返すのは HTML の**文字列**で、
流し込むには `innerHTML` が要る。ログ本文を出す場所なので、そこは譲れない。
依存パッケージを増やさない決まりもある。だから自分で書いてある。

分け方はこのプロジェクトの他所と同じ。**判断（純関数）と I/O（薄い殻）。**

| ファイル | 何をするか | DOM |
|---|---|---|
| `md.js` | 文字列 → ブロックの並び（`parseMarkdown`） | 触らない |
| `md-view.js` | ブロックの並び → 節点（`mdBlocks` / `mdView`） | `document.createElement` だけ |

だから `md.js` は Node から import できて、`test/md.test.mjs` に全分岐が乗っている
（件数は書かない。テストを1件足すたびに腐る）。
`parseUpdateState`（判断）と `loadUpdateState`（I/O）を分けたのと同じ形。

**描く記法はこれだけ。** どれも実測（会話ログ）で数えて決めた。

```
ブロック   見出し / 段落 / コードフェンス / 箇条書き / 番号付き / チェックリスト / 表 / 水平線 / 引用
インライン インラインコード / 太字 / 打ち消し / リンク（http・https だけ）/ 素の URL / 表のセルの <br>
```

**出さない記法**は素の文字として残る。作らなくても「いまと同じ見え方」なので、作らないことの害が無い。

| 記法 | 出さない理由 |
|---|---|
| 斜体（`*` 1つ・`_` 1つ） | `*.js` のようなふつうの文字列が斜体に化けるほうが害が大きい。箇条書きの記号とも衝突する |
| Wiki リンク（`[[x]]`） | 行き先が ClaudeDeck の外（Obsidian の中）にあり、押しても開けない |
| 画像（`![alt](url)`） | ログ本文から外の画像を読みに行かせない。中の URL も素の URL として拾わない（丸ごと素の文字） |
| HTML（`<b>` など） | `innerHTML` を使わない約束そのもの。例外は表のセルの `<br>` だけで、それも改行の意味だけを拾う |
| シンタックスハイライト | フェンスの言語指定が 885 件のうち 852 件で「なし」 |

最初の9つ（コード・太字・フェンス・箇条書き・番号付き・見出し・表・水平線・チェックリスト）は
assistant の本文で数えた。残りは**新しい順 80 ログ（2026-10-08。assistant 1,936 件・指示文 473 件）**で数えて足した。

| 記法 | assistant | 指示文 | 前の扱い |
|---|---|---|---|
| 太字の中のコード（`**チェッカー（`x.py`）**`） | 85件（4.4%） | 76件 | バッククォートがそのまま太字で出ていた |
| リンク `[表示名](URL)` | 4件（0.2%） | — | 表の中で記号ごと出ていた |
| 素の URL | 13件（0.7%） | 21件 | 押せない文字だった |
| 引用 `>` | 3件 | 58件（12%） | `>` が行頭に並んでいた |
| 表のセルの `<br>` | 1件 | 1件 | `<br>` が文字で出ていた |
| 打ち消し `~~` | 2件 | — | `~~` が文字で出ていた |

**引用は指示文のための記法。** assistant にはまれだが、時系列はあなたの指示文も Markdown で描いているので、
そちらの 12% に効く。行頭（先行空白 0〜3）の `>` が続く行を1つにまとめ、中身を `parseMarkdown` で
もう一度読む。空行か `>` の無い行で終わる（`>` の無い続きの行は引用へ含めない。指示文の地の文を飲み込むほうが害が大きい）。
**入れ子は8段まで**（`MAX_QUOTE_DEPTH`）。超えたぶんは素の文字の段落にする。上限が無いと `>` を数千並べた1行で
再帰が深くなり、RangeError で時系列の描画ごと落ちる。同じ理由で、リンクの表示名と URL を探しに行く長さにも上限がある
（`[a](x` の繰り返しで2乗の時間にしない）。

**表のセルの `<br>` は改行にする**（コードの中は変えない）。Markdown には表のセルの中で改行する書き方が無いので
`<br>` が使われる。HTML としては描かず、`\n` に直して CSS の `pre-line`（見出し行は `pre`）で出す。

### インラインの形（平らな run ＋ 印）

`inlineSpans` は `{ type: 'text' | 'code', v, strong?, del?, href? }` の**平らな並び**を返す。
太字の中のリンクのような入れ子も、run ごとに印を重ねて表す。**木にしない。**
`spansText` / `cutSpans`（頭出し）/ `blocksText`（検索件数の物差し）が `v` を繋ぐだけで動くため。
`cutSpans` は `{ ...s, v }` で複製する（印を落とすと頭出しだけ太字やリンクが消える）。

器へ組み直すのは `md-view.js` の `spanNodes`。続いている run のうち印が同じものを1つにまとめ、
外から `a > strong > del` の順で包む。まとめないと、太字の中のリンクが a 2つに割れて下線が途切れる。

読む順はコード → 太字・打ち消し → リンク → 素の URL。
コードの中は何も読まない。太字と打ち消しは閉じがあれば中身を**もう一度インラインとして読む**
（太字の中の太字は見ない）。閉じが無ければ素の文字（下の「途中で切れた入力」）。

### リンク（http と https だけ）

**`href` に入れてよいのは `/^https?:\/\//i` に当たるものだけ。** `md.js` と `md-view.js` の両方で確かめる
（境界を1枚にしない。式は `md.js` の `SAFE_HREF_RE` の1つ）。前はリンクそのものを
「`javascript:` を弾く検証を 0.2% のために抱えたくない」で見送っていたが、表の中の `[表示名](URL)` が
記号ごと出て読めず、素の URL のほうが多かった。弾く検証は1本の正規表現で済む。

| 来たもの | 描き方 |
|---|---|
| `[表示名](https://…)` | 表示名をリンクにする |
| `[表示名](javascript:…)` / `[表示名](./a.md)` / `mailto:` | **リンクにせず表示名だけ**。記号と URL は捨てる |
| 素の `https://…` | リンクにする。直前が英数字なら読まない。日本語の 」 や 、 で止まる（URL の文字は ASCII だけ） |
| `![alt](url)` / `[[x]]` | 素の文字のまま |

**相対パスを通さないのは、ClaudeDeck から開けないから。** 会話ログが書いた相対パスは
そのリポジトリから見た場所で、`127.0.0.1:4317` の下には無い。押して 404 を出すより、押せないほうがよい。

素の URL の末尾の `.,;:!?'"` と、対応する `(` の無い `)` は外す。`(https://…)` の閉じ括弧や
文末の句点までリンクに飲まないため。対応の取れた括弧（Wikipedia の `Foo_(bar)`）は残る。

**a は `target="_blank"` と `rel="noopener noreferrer"` で作り、`title` に URL を出す。**
このページを置き換えると一覧と詳細の状態が消える。表示名だけでは行き先が読めないので、押す前に確かめられるようにする。

**`blocksText` はリンクの URL を数えない。** 画面に出るのは表示名だけなので、URL まで数えると
「一致 N 件」と画面の色が食い違う（素の URL は画面にそのまま出るので数える）。

**リンクを押しても祖先のクリックは起きない**（2026-10-08 に調べた）。`.md` が入る場所
（時系列の項目・「全文」の `details`・プランの系譜・待ちのパネル・許可要求のカード）の祖先に
`click` の受け手は無い。カードと行の `click`（`list.js` / `archive.js`）は一覧の側で、`.md` は入らない。
`<summary>` の中にもリンクは入らない（中身は器の外で組んだ固定の文言）。
**`.md` を一覧のカードや押せる行の中に入れるときは、リンク側で `stopPropagation` が要る。**

### 箇条書きの詰め方

**項目の間は margin ではなく行間で詰める**（`.md-list li` の `line-height: 1.55`。表と同じ）。
前は `li + li` に `.4em` を足していたが、見た目の隙間の大半は `.md` の行間（1.78）から来ていて、
margin だけ半分にしても約18px → 15px でほとんど変わらなかった。margin 0 ＋ 行間 1.55 で約8px
（モックで3案を比べた案C）。前後のブロックとの間（`.85em`）は変えない。

**空行を1つ挟んだ項目だけ離す**（`md.js` の `gap` → `li.is-gap` → `.85em`）。書いた人が空行で
塊を分けているので、詰めたぶん離さないと区切りが消える。リストは割らないので番号は続く。

### チェックリスト（`- [ ]` / `- [x]` / `- [~]`）

**後から足した。** 最初は「0%」で見送ったが、それは数えた場所が違っていた。
**来るのは assistant の本文ではなく、プランの本文とユーザーの指示文。**

| 出どころ | 見つかった件数 | 行数 |
|---|---|---|
| assistant の text（20ログ・2,534件） | 0件 | 0 |
| プランの本文（40ログ・30件） | 1件 | 5 |
| ユーザーの指示文（40ログ） | 15件 | 129 |

承認待ちのプランは**切らずに全部描く**場所なので、そこに素の `- [ ]` が並ぶと、
どこまで終わったのかが読めない。

**印は CSS の `::marker` で出す。** 節点に文字を入れない。理由は3つ。

- 本文を選択してコピーしたときに混ざらない（`.md.is-cut::after` の「…」と同じ理由）
- bullet と同じ場所に入るので、印の無い項目と同じリストに混ざっても本文の左端が揃う（実測で全項目 `left: 588`）
- `list-style` を切って印の位置を自分で作らなくて済む

`::marker` で使えるのは `content` と `color` と `font-*` だけなので、図形は描かずに字を置く。

**記号と色は TODO パネル（`panels.css`）から借りる。** 同じ詳細ペインに並ぶので、
同じ「済んだ」を片方は ✓・片方は別の印で描くと、別の意味に見える。**色は1つも新しく作らない。**

| 記法 | `data-task` | 記号 | 色 | 借り元 |
|---|---|---|---|---|
| `- [ ]` | `todo` | □ | `--fg-faint` | — |
| `- [~]` | `doing` | ■ | `--accent` | `[data-status="in_progress"]` |
| `- [x]` `- [X]` | `done` | ✓ | `--done` | `[data-status="completed"] .st::before` |

**`- [~]`（進行中）は GFM に無い。Claude が独自に書くもの。**
実測1件で、TODO の `in_progress` と同じ意味で使われていた。

**受ける記号はこの4つだけ。** 中を1文字なら何でも通す形にすると、
`- [2] 消す対象の一覧とサイズを記録` のような手順の番号が空のチェックボックスに化ける
（実測4件。ユーザーの指示文）。印の後ろは空白か行末に限る（`- [x]abc` は記法として曖昧）。

**印は `md.js` が本文から剥がす。** 残すと画面に `□ [ ] やること` と二重に出るうえ、
`blocksText`（切る予算と「一致 N 件」の物差し）にも入ってしまう。

**済んだ項目は本文の色を1段落とす**（`--fg-faint`）。**取り消し線は付けない。**
TODO パネルの `.subject` は1行の短い題だが、こちらは長い文が来る
（実測でプランの1項目が「Phase 1: 初期理解 (Excel対象把握 …) — 探偵A/B 完了」）。

**途中で切れた入力が日常的に来る。** `clip()` が「…（以下省略）」を足すので、
`**` が片方だけ・フェンスが閉じていない・表が途中で終わる、が普通に届く。
閉じていない記号はただの文字として残し、閉じていないフェンスは `open` を立てて破線で示す
（言葉は足さない。本文に既に「…（以下省略）」が書かれているので二重に報告することになる）。

**検索の目印（`<mark>`）は装飾の中でも効かせる。** 太字やコードの中に当たった語が入ったとき、
記法を描いたせいで目印が消えると「一致 3 件」と出ているのに画面のどこにも色が付かない。
だから `markUp` / `marked` を span ごとに通す（この2つを層0 の `util.js` へ移したのはこのため）。

**見出しは2段下げる。** パネル側が `h3` を使っているので、本文の `#` をそのまま `h1` で出すと
階層が逆立ちする。見た目の大小は元の段（`.md-h1`〜`.md-h6`）が持つので、6 で頭打ちにしても潰れない。

**段の差は「大きさ」「上の余白」「線の太さ」で付け、h4 以下は色で示す。**
どの段が実際に来るのかを数えた（`~/.claude/projects` の大きい順）。

| 出どころ | 見出しを持つ件数 | h1 | h2 | h3 | h4 | h5 | h6 |
|---|---|---|---|---|---|---|---|
| プランの本文（40ログ） | 30件・全件 | 48 | 267 | 351 | 13 | 0 | 0 |
| assistant の text（20ログ） | 2,534件中 202件 | 13 | 630 | 83 | 0 | 0 | 0 |
| ユーザーの指示文（40ログ） | 40件中 26件 | 77 | 245 | 142 | 17 | 0 | 0 |

**h1〜h3 の3段は揃って来る**（プラン30件のうち28件。1件で最大118個・平均 10,402字）。
h4 はまれ（プラン1件・指示文5件）で、**h5 と h6 は3経路すべてで0件。**
いちばん大事なパネル（承認待ち・切らずに全部描く）に118個の見出しが並ぶので、
段が読めないと流し読みができない。

寸法は**比で持つ**（`em`）。本文は `--fs-4`（15px）。

| 段 | 比 | 読む面・時系列（15px） | 上の余白 | 下線 | 色 |
|---|---|---|---|---|---|
| h1 | ×1.405 | 21.07px | 2.4em（36px） | 2px `--accent` 60% | `--fg` |
| h2 | ×1.238 | 18.57px | 1.95em（29.3px） | 1px `--accent` 30% | `--fg` |
| h3 | ×1.107 | 16.61px | 1.45em（21.8px） | なし | `--fg` |
| h4 | ×1.024 | 15.36px | 1.1em（16.5px） | なし | `--fg-muted` |
| h5・h6 | ×1 | 15px | 1.1em（16.5px） | なし | `--fg-muted` |

**px ではなく `em` で持つ理由。** 器の大きさに追従させるため。
`.md` は読む面（`--fs-4`）と時系列（`.md.tl-text` で `--fs-3`）の2つの尺で使われるので、
px で書くと**どちらか片方でしか比が合わない**。実測で決めた比はそのまま保ってある
（前は `rem` で 1.18 / 1.04 / .93 と書いてあり、本文 `.84rem` に対する倍率がこの値だった）。
いまは2つの尺がどちらも 15px で同じ値だが（「段（スケール）」の節）、トークンは別なので `em` のままにしておく。
前は時系列が 14px で、見出しも1段小さく出ていた。

**線は上2段だけ。** 全部に引くと本文より罫線のほうが目立つ（118個並ぶプランではより効く）。
h1 と h2 は線の有無ではなく太さで分ける。
線の色は `color-mix()` で `--accent` に寄せてある（h1 は 60%、h2 は 30%。残りは `--border`）。

**色を付けるのは「目印」だけ。** 見出しの線・箇条書きの点と番号・表の見出し行の面（`--accent-soft` を重ねる）・
文中のコードの字。**見出しの字と本文は塗らない。** 字まで `--accent` にすると、選んでいるタブや
「全文」の畳み（押せるもの）と同じ色になり、見出しが押せそうに見える。3案（白一色・目印だけ・見出しの字も）を
モックで並べて決めた。状態色（`--hot` `--warn` `--calm` `--done`）は意味を持つので使わない。
見出しの左に縦棒も付けない（時系列では `--accent` の左の縦棒が「あなたの発言」の印）。

**h4 を大きさで押さない。** h3 が 16.61px、本文が 15px なので、あいだに置くと h3 との差が
1px ほどしか作れない（h4 と本文の差は 0.36px）。**本文を上げたぶん、その差はむしろ縮んだ。**
数えたときは h4 はまれだったが、13個入っているプランが実物にあり、
h3 の直下に来ると文字だけでは見分けが付かなかった。だから色を1段落として示す。

上の余白は段別に4行で書く。どれも詳細度は (0,2,0) なので、**深い段から浅い段の順に書いて
後を勝たせる**（`.md > .md-hr` と同じ形）。見出しの直後だけは詰める（`.md > .md-h + *`）。
上を空けて下を詰めると、見出しがその下の塊のものだと余白だけで読める。

**頭出しで切ったときは、末尾に残った見出しの線を落とす**（`.md.is-cut > .md-h:last-child`）。
後ろには切り跡の「…」しか来ないので、区切る先の無い線になる（`headBlocks` が末尾の `hr` を
落とすのと同じ理由）。`md.js` ではなく CSS で閉じているのは、あちらを直すと
`headBlocks` のテストに触ることになるため。

描いているのは5箇所。**時系列の頭出しも含む。**

| 場所 | 呼ぶ人 |
|---|---|
| 時系列の頭出し | `timeline/blocks.js` の `bodyText` |
| 「全文」の畳んだ中 | `timeline/blocks.js` の `bodyText` |
| プランの本文（提出したとき） | `timeline/blocks.js` の `planBlock` |
| プランの本文（いまのファイル） | `timeline/blocks.js` の `lineageNodes` |
| 待ちのパネルのプランと最後の応答 | `detail-wait.js` |

**頭出しは切る単位をブロックにする。** 文字数で切ると記法の途中で切れた断片を描くことになる
（`**` が片方だけ残った、表が途中で終わった）。`headBlocks` は予算に収まるブロックだけを入れ、
入り切らない1つは中で切る（表は**見出しの行を予算より優先して**残し、箇条書きは項目ごと落とす）。
末尾に残った区切り線は落とす。後ろには切り跡しか来ないので、区切る先の無い線だけが残る。

**パースは1件につき1回。** 頭出しと「全文」は同じ結果から描く（だから `mdBlocks` の口がある）。
文字列を受ける口しか無いと、1件を2回パースすることになる。

**物差しは1つ（`blocksText`）。** 切る予算も「一致 N 件」も、描いたあとの文字で数える。
片方を素の文字列にすると、画面に出ていない記号まで数に入って両者が食い違う。

**切り跡の「…」は CSS の `::after` で出す**（`.md.is-cut`）。節点にすると、
本文を選択してコピーしたときに混ざる。切ったことを `open` で表さないのも同じ理由で、
あちらは「源のフェンスが閉じていない」の意味だけを持たせてある。

**器は `.md` と `.tl-text` を併せて付ける。** 種類ごとの装飾（`prompt` と `echo` の枠・
`say` と `recap` の色）はあちらが持っているので、`timeline.css` と `run.css` を1行も触らずに済む。
ただし `.tl-text` の `white-space: pre-wrap` をそのまま継ぐと表のセルだけ見え方が変わるので、
`.md` の側で `normal` を明示する（同じ詳細度なので、`markdown.css` を後に読むことで勝っている）。

実測（開発サーバー・時系列 74件）。60件を一気に継ぎ足す描き直しは 23.0〜30.3ms で、
Markdown 化する前の同じ操作が 28.3〜34.5ms。**この操作は元から 16ms を超えている**ので、
目安を超えているのは事実だが、Markdown にしたことによる退行ではない。
パースそのものは 57件・6,483字で 6.7ms（1件あたり 0.12ms）。

**プランの2つは描き方を揃える。** 見比べるために並べているものなので、
片方だけ Markdown にすると、同じ文でも別物に見える。

高さの上限は**器の側**が持つ（`.is-block .md` が 24rem。答えないと進まない待ちだけ）。
「全文」の畳んだ中と、返信待ち（「いま」タブ）の最後の応答には上限を付けない。
箱の中でスクロールさせるとページのスクロールと二重になり、読みにくかった（実測の指摘）。
`.md` 自身に持たせない。どのパネルへ入れても同じに見える、という前提が崩れる。

## 触るときに壊してはいけないこと（画面側）

- **詳細ペインの待ちのパネルの見出し「あなたの番」を、止まっていない待ちに付けない。** 判定は `row.blocking`（サーバー由来）だけを見る。付ける先は `detail-wait.js` の `headingOf()` と `run-ask.js` の1箇所ずつで、**そこ以外に増やさない**。返信待ちは `row.stateLabel` から「返信待ち — 次の指示を出す」を組む（Claude は応答を返し終えていて、放置しても壊れるものが無い）
- **一覧の枠「あなたの番」はボールの所在の束で、返信待ちも入れる。** 上の詳細ペインの見出しとは問いが違う（あちらは「答えないと進まないか」、こちらは「誰の番か」）。枠の中を小見出し2つ（許可・質問で止まっている／返信待ち。`groups.js` の `YOURS_GROUPS`）に分けて、急ぐほうを先に置く。**左のレールの作業台のバッジは止まっているものだけを数える**（`meta.stateBlocking`）ので枠の件数とは別の数になるが、札の名前が「止まっているもの N 件」と言っているので食い違わない。拡大モーダルの「次の待ち」も止まっているものだけを回り、頭の数は「止まっている i / N」と言う（「あなたの番」と言うと枠の件数と食い違って見える）
- **急ぎの印を新しい色で作らない。** `.panel.is-block` は**太さ（左の 3px）と見出し1段だけ**。色は既存の `.panel.is-hot` の**見出しの字**が持つ（`--hot` は「止まっている」の色で、急ぎの印はまさにそれ）。左の太い線は無彩色（`--border-strong`。細い枠の `--border` だと太さが読めない）で、色を見分けにくい人にも届く印として太さだけを残してある。新しい色を作ると「1色に役は1つ」が崩れ、`test/tokens.test.mjs` の並びにも足すことになる。面も塗らない。タブの帯にも足さない（隣のタブの位置が動いて押し間違いが起きる）。**許可要求カード（`.ask`）の左の線も同じく無彩色**（外のパネルの赤い見出しと同じことを言っていた）
- **待ちのパネルに案内文を戻さない。** 見出しの下の1行（「このツールを実行してよいかを決めてください」など）は見出し（「あなたの番 — 実行を許可する」）と同じことを言うだけだった。表（`WAIT_GUIDE` / `ASK_GUIDE`）にも文を持たせない。返信待ちの最後の応答に「Claude の最後の応答」の札も付けない（見出しが「返信待ち — 次の指示を出す」と言っている）。**札ではなく中身のものは残す** … 「プランの保存先 ＜パス＞」はパスそのものが中身、許可要求が複数のときの「すべて答えるまで、この先へ進みません。」は件数の情報（`test/detail-pane.test.mjs` が字面で見ている）
- **`is-wait` を `is-block` に置き換えない。** あれは**レイアウトの印**で、`detail.css` の縦積みが付いている。返信待ちのパネルにこそ Markdown が入る。逆に**高さの上限（24rem）は `.is-block .md` に付けてある** … 上限が要るのはタブ帯の直下にどのタブでも出る待ちだけで（長いプラン1本で、選んだタブの中身が画面の外まで押し出される）、「いま」タブの中の返信待ちに付けると二重スクロールになる
- **Markdown を描くのに外の道具を持ち込まない。** `marked` も `markdown-it` も返すのは HTML の**文字列**で、流し込むには `innerHTML` が要る。依存パッケージを増やさない決まりもある。自作の `md.js` ＋ `md-view.js` で通す
- **`md.js` に DOM を触らせない。** あれが Node から import できてテストに乗っているのは、`document` を1つも見ていないから。判断（`md.js`）と I/O（`md-view.js`）を混ぜると、画面側のテストが動かなくなる
- **閉じていない記号を装飾に化かさない。** `clip()` が「…（以下省略）」を足すので、`**` `~~` `[` が片方だけ・フェンスが開いたまま、が日常的に届く。装飾として読むと、そこから先が全部太字になる
- **閉じていないフェンスに言葉を足さない。** 本文に既に「…（以下省略）」が書かれている。`.md-pre.is-open` は線を破線にするだけにする（二重に報告することになる）
- **装飾の中でも `markUp` を通す。** 太字・打ち消し・リンク・コードの中に当たった語が入ったとき目印（`<mark>`）が消えると、「一致 3 件」と出ているのに画面のどこにも色が付いていない状態になる
- **リンクを作るのに `innerHTML` も文字列の組み立ても使わない。** `el('a', 'md-link')` で作り、`href` は**スキームを確かめてから**プロパティで代入する。確かめる式は `md.js` の `SAFE_HREF_RE`（`/^https?:\/\//i`）の1つで、`md.js` と `md-view.js` の両方が通す（境界を1枚にしない）
- **`href` に http / https 以外を入れない。** `javascript:` を通したらログ本文を書いた誰でもこの画面でスクリプトを走らせられる。相対パス・`mailto:` も通さない（相対パスは ClaudeDeck から開けない）。外れたものは**リンクにせず表示名だけ**を出す。記号ごと素の文字に戻すと表の中が読めなくなる（前の状態）
- **リンクは `target="_blank"` ＋ `rel="noopener noreferrer"` で開く。** このページを置き換えると一覧と詳細の状態が消える。`noopener` を外すと開いた先が `window.opener` からこの画面を触れる
- **spans を木にしない。** 平らな run に印（`strong` / `del` / `href`）を付ける形にしてある。木にすると `spansText` / `cutSpans` / `blocksText`（頭出しと検索件数の物差し）を全部書き直すことになる。`cutSpans` で複製するときは `{ ...s, v }` で印ごと持っていく
- **`blocksText` にリンクの URL を入れない。** 画面に出るのは表示名だけ。URL まで数えると「一致 N 件」と画面の色が食い違う
- **`.md` を押せる器（一覧のカード・行）の中に入れるなら、リンク側で `stopPropagation` する。** いまは `.md` の祖先に `click` の受け手が無いので何もしていない（2026-10-08 に調べた）
- **チェックリストの印を DOM に入れない。** `::marker` で出す（`.md-list li[data-task]`）。節点にすると本文を選択してコピーしたときに混ざる（切り跡の「…」と同じ理由）。`md.js` が印を本文から剥がしているので、CSS 側で出しても二重にならない
- **チェックリストの印を「中を1文字なら何でも」で読まない。** 受けるのは `[ ]` `[x]` `[X]` `[~]` の4つだけ。緩めると `- [2] 消す対象の一覧とサイズを記録` のような手順の番号が空のチェックボックスに化ける（実測4件。ユーザーの指示文）。印の後ろは空白か行末に限る

- **`/api/runs/events` の窓口は、画面が使わなくなっても消さない。** 入口の名前と応答の形は変えない約束があり、`?from=` の穴埋めを受け持つのはこの窓口
- **`runs.js`（層2）から `run-view.js`（層3）を import しない。** 逆向きになる。`subscribeRuns(fn)` で外から登録し、配線するのは `main.js`（層8）。既存の循環4箇所と同じ切り方
- **未応答の許可要求を速報から読まない。** 画面は速報を1件も持たない（溜めていた頃も 400 で溢れたぶんを捨てていた）。**要求を載せると消えて二度と答えられない。** 行（`row.asks`）から読む。`rows` は毎フレーム総入れ替えなので、取りこぼしが次のフレームで自己修復する
- **押しても画面からカードを消さない。** 消す権利はサーバーだけが持ち、画面は `row.asks` から消えるのを待つ。先に消すと、サーバー側で失敗していたときに**「消えたのに答えられていない」**という最悪の状態になる。成功しても `sending` を `null` に戻さないのは同じ理由
- **`sending` を解くのは `askBlock()` の入口の1箇所だけ。この行を消さない。** 成功時に `send()` が戻さない以上、「サーバーが消した」ことを行そのもので確かめる場所がどこかに要る。無いと、答えたあとに来た**次の要求のボタンが無反応になる**（`send()` 冒頭の即 return に食われる。実測。1回リロードすると直るのが目印だった）
- **`await` の後は `sending !== askId` を確かめてから書く。** 返ってくるまでに別のセッションへ移っていることがあり、確かめずに書くと他人の画面へ結果を出す（`run-view.js` の `post()` が `ops.runId !== runId` を見ているのと同じ作法）
- **要求カードを `run-view.js` に足さない。** 行数ではなく**ライフサイクルが違う**。あちらの `ops` は「入力中のテキスト」「開いた `<details>`」「速報の水位」を溜めて作り直しから守る作りで、要求カードは追記されず答えたら消える。混ぜると `applyEnabled()` の `ops.busy || ops.over` に性質の違う4つ目が入り、`setBusy(true)` が要求カードのボタンまで殺すかの判断が毎回要る
- **プラン承認に「承認したまま plan に留まる」道を出さない。** ボタンは `allow` ＋ 行き先のモードを束ねた形にする。`ExitPlanMode` を許可しただけでは plan から抜けないので、分けると「承認したのに書けない」を人が選べてしまう（これが 0.7.1 までの「bash で止まる」の正体）
- **`/mode`（子を殺さず替える）と `/switch`（建て直す）の振り分けは画面がやる。** 子が生きていて替えるのが権限モードとモデルだけなら `/mode`、それ以外は `/switch`。サーバー側の窓口を「どちらもできる1本」にすると、呼ぶ側から見て指示文が要るときと要らないときがある窓口になる。**ボタンの文言は替えず、下の1行だけを差し替える**（押そうとした位置が動かない）
- **要求カードから実行パネルの節点を掴まない。** カードの下に出す案内は**押せない文だけ**にする。`run-view.js` の札を押しに行くと `run-ask.js` → `run-view.js` の向きができて、`RUN_OVER` をあえて重複させている今の切り方が崩れる
- **替える口を実行パネルの中に置かない。** 速報が数百行伸びていた頃、パネルの中に置くと**いちばん替えたい場面（走っている最中）に限って画面の下へ流れて見つからなかった**（実測。0.7.1 の `<details>` がそうなっていた）。速報を外してパネルが短くなったいまも外に出したままにしてある。詳細ペインは作り直されるので、中に置くと入力中の値と開いた窓が消える。いまは入力欄のすぐ上の札（`.composer-now`）が入り口で、中身は `document.body` に付けた `<dialog class="runsw">`。**どちらも詳細ペインの外**なので作り直しに巻き込まれない
- **別の実行へ移ったら替える窓を閉じる。** `<dialog>` はペインの外にいるので、黙っていると開いたまま残る。前の実行の値が入った窓で押すと、**いまの実行にその値が当たる**。閉じるのは `syncOps()` の `ops.runId !== row.runId` の枝と、`composerFor()` が `null` を返す枝の2つ
- **モデルを自由入力だけにしない。** 何を書けばいいのか分からない（実測の指摘）。候補は `/api/runs/options` の `models`（サーバーが一覧から拾った、実際に使われたモデル）で、そこに無い名前は「自分で入力」から渡せる。値の割り方と組み立て（`MODEL_FREE` / `modelOptions` / `modelPick` / `modelValue`）は `runs.js`（層2）に置き、**層3と層7の両方から使う**。それぞれに残すのは入力欄の出し入れだけ
- **実行パネルを詳細（`d`）の中に入れない。** 起こした直後はまだ会話ログが1行も無く、`d` は null。中に入れるとログが出るまで何も出ず、押したのに何も起きていないように見える
- **起こしたセッションを `select(id, 'live')` で選ばない。** `'query'` にする。起こした直後は一覧にまだ並ばないので、`'live'` で選ぶと次の push（2秒後）に `stream.js` の `apply()` が「一覧から消えた」と読んで選択を外し、先頭のセッションへ飛ぶ
- **めったに触らない3つ（モデル・思考量・上限）は畳む。** 毎回書くのは指示欄だけで、あとは既定のまま押すことがほとんど。**畳んだ札には中身を書く**（「詳細設定」のような空の名前にすると、開かないと分からなくなる）。上限は金が減る話なので、既定のままでも必ず出す
- **権限モードは畳まない。** ここは危ないほうへ倒せる唯一の欄で、`bypass permissions` を選ぶと何も確認せずに走る。**畳む基準は「触る頻度」だけでなく「間違えたときの重さ」も見る**
- **開くたびに畳んだ状態へ戻す。** 前に開いたかどうかを覚えると、起こすたびに違う高さの画面が出る
- **上端を固定して、下だけ伸ばす**（`margin-top` を置いて `margin-bottom: auto`）。畳みを開くと中身が 120px 増える。`<dialog>` の既定（`margin: auto`）は中央に置くので、その半分だけ上端が動き、押す位置も一緒に動く（実測で 60px）。設定モーダルは高さそのものを固定してあるが（節ごとの差が小さいので空白が出ない）、**結果はどちらも「上端が動かない」で同じ**
- **絵は「読み飛ばすな」の場所に置く。** 警告と、危ない権限モードの但し書きの2か所。ラベル3つ（作業フォルダ・最初の指示・権限モード）にも置くが、**グリッドの中（モデル・思考量・上限）には置かない**。絵が縦に何個も並ぶと、いちばん読ませたい警告が「並んでいるうちの1つ」になる
- **危ない権限モードは色だけで伝えない。** 但し書きに三角を出すのに加えて、選ぶ欄そのものの枠も赤くする（`is-danger`）。畳みの下を見ているあいだ、但し書きだけだと欄の状態が視界から外れる
- **`[hidden]` で出し入れするものに `display` を素で書かない。** `[hidden]` のブラウザ既定（`display: none`）は詳細度 0,1,0 しかない。`.runform-danger.has-icon` のような 0,2,0 を素で書くと `display: flex` が勝ち、**`plan mode` を選んでいても「何でも実行します」が出たままになる**（実測）。`:not([hidden])` を付けて逃げる
- **起こした直後に画面を勝手に動かさない。** モーダルを閉じて詳細ペインへ飛ばすと、会話ログが出るまでの数秒「このセッションは開けませんでした」を見せることになる。結果はモーダルの中に出して、移るかどうかは押した人に決めてもらう
- **起こすフォームの見た目を新しく作らない。** 中身は設定モーダルのクラス（`.settings-head` / `.settings-body` / `.settings-sec` / `.settings-label` / `.settings-row` / `.settings-hint` / `.settings-grid` / `.settings-text` / `.settings-num` / `.settings-select` / `.settings-foot` / `.settings-msg`）をそのまま借りる。あちらのセレクタは `.settings` を親に取っていないクラス単体なので、`.runform` の中でも効く。`run.css` に書き写すのは `.settings` 自身に紐づく4つ（本体・`::backdrop`・`[open]`・幅）だけ。**替える窓（`.runsw`）も同じ借り方**にする（器の4つだけ自前）
- **キー操作の判定にクラス名を使わない。** 見た目を借りている以上、`.settings-text` のような借り先の名前が `run-form.js` に書かれることになる。要素名（`input, select`）で見て、本文欄だけは参照（`ev.target === dom.runPrompt`）で分ける
- **パレットに「止める」「替える」「続ける」を出さない。** どれも子プロセスを畳む（あるいは起こす）操作で、Enter ひと押しで走ってしまう。打った文字で並びが動くので、狙っていないものを実行する事故が起きうる。この3つは実行パネルの押しやすい場所にあるので、そちらで足りる（出すのはモーダルが開くだけの「起こす」と「拡大」、窓が出るだけの「ターミナルを前面に」の3つ）
- **パレットに個別のショートカット（Ctrl+N など）を足さない。** Ctrl+K 以外はブラウザが先に取っているものが多く、奪えないキーを画面に書くと「押しても効かないキー」を案内することになる
- **`exec()` で閉じるのを実行より先に置く。** `<dialog>` は閉じるときに開く前の焦点へ戻すので、焦点を動かすもの（一覧を出す）を先にやると、せっかく移った焦点をこちらが奪う。結果を読ませたいもの（`keepOpen`）だけ閉じずに残す
- **パレットの `scrollIntoView` は、直前がグループ見出しならそちらを寄せる。** `block: 'nearest'` は「見える範囲に入っていれば動かさない」ので、項目そのものを寄せると見出しが上に隠れ、どの群にいるのか読めなくなる（末尾から先頭へ巻き戻ったとき、実測で 28.8px ぶん隠れていた）
- **`applyOptions()` を再描画のたびに当てない。** 詳細ペインは他の理由でもよく組み直されるので、毎回 `defaultMode` と `budget.default` を代入し直すと、選んだモードと予算が黙って既定へ戻る。`ui.filled` で1回だけにして、落とすのは別のセッションへ移ったときだけ
- **狭い画面のインスペクタを別のセルへ置かない。** 単一列の `.deck` に in-flow の子が3つ（`.detail-pane` / `.insp` / `.rail`）あると2列から溢れて暗黙の2行目ができ、レールが画面の下で横倒しの帯になる（段2 で実測）。`grid-area` を明示して1行2列へ押し込む（`.detail-pane` と `.insp` を `1 / 1` に重ね、`.rail` を `1 / 2`）。こうすれば重ねる紙が何枚あっても行は増えない。`position: fixed` で浮かせる手もあるが、そちらはレールの幅を `right: <幅>` として二重に書くことになる
- **ボトムシートに膜を敷かない。** レール（`z-index` を持たない）がその下に潜り、開く口と閉じる口を兼ねているレールの設計が狭い画面だけ崩れる。閉じる口は紙の頭の × と、押したのと同じレールのボタン（`setInspector` はトグル）の2つで足りる
- **`.insp` に `z-index` を付ける。** 重なりの順は DOM の並びでは決まらない。中央の中にあるタブの帯（`.detail-tabs`）が sticky ＋ `z-index: 2` なので、印を付けない紙はその下へ潜り、閉じるボタンの上にタブが透けて出る。grid item は `position: static` でも `z-index` が効くので1つ足すだけで済む
- **紙の出方を `transition` で書かない。** `.insp` は JS が `hidden` で消すので `display: none` から現れ、遷移の1フレーム目が無い。`animation` にすれば `base.css` の `prefers-reduced-motion` が `animation-duration` を潰すのでただ乗りできる
- **書庫を作業台と同居させない。** モードとして分ける（`store.mode`）。同居させると「いまの作業」と「過去を探す」が同じ画面で場所を取り合う。片方を見ているあいだ、もう片方は `archive.css` の `.is-archive` で丸ごと消す
- **一覧で並べ替えない。** `store.rows` はサーバー側が `STATE_RANK` と開始時刻（終了済みだけ `idleMs`）で並べたものなので、前から拾って束へ振り分けるだけでよい（`groups.js` の `groupRows`）。比較器を2箇所に書かない（畳んだ監視盤も同じ考えで列へ振り分けていた）。束の中も入ってきた順のまま（`test/groups.test.mjs` が見ている）
- **束は上から あなたの番 → ピン留め → 実行中 → 終了 → そのほか。** どの束へ置くか（判断）と束の定義（ピン留めとそのほかも含む）は `groups.js`、描くのは `list.js` の `renderList`。どの束にも入らない状態は「そのほか」へ落とす。**黙って落とさない**（サーバー側が状態を1つ足した日に、一覧から行が消えるほうが困る）
- **`list.js` に状態の名前も束の id も書かない。** 止まっている行かどうかは `groupRows` が振り分けた束で決まっている（行の2行目は束の `wants`、開け閉めは束の `foldable`、見出しの点か絵かは束の `states` / `icon` を読む）。`STOP_STATES.has(row.state)` のように引き直したり `group.id === 'done'` で分岐したりすると、束を1つ足した日に `groups.js` と食い違う（`test/screen.test.mjs` が字面で見ている）。例外は「動いている行か」の `'running'` だけ … ピン留めに入った動いている行も「いま何をしているか」を出すので、束からは決められない
- **一覧も鍵が変わったときだけ組み直す**（`listKey()`）。**材料は `groupRows` の結果から作る**（描くものと同じ形から作れば、鍵と画面が食い違わない）。見るのは束ごとの「どの行が、どの状態で、どんな題で並んでいるか」と、行に出す印（ピン・メモ）、枠の行の札「画面」の有無、`wants` の束の行の「何を求めているか」、`store.onlyLive`、meta を受け取ったか、開いている束。**経過時間と「いま何をしているか」を鍵に混ぜない**（毎秒・数秒ごとに動くので鍵の意味が消える）。毎回 `replaceChildren()` すると、スクロール位置が先頭へ飛ぶだけでなく、**焦点を持っていた `.row` が破棄されて上下キーが push と push の間しか効かなくなる**（`main.js` の上下キーは焦点が `.row` の中にあることが前提）。経過時間と「いま何をしているか」は `refreshTimes()` が、選んでいる印は `select()` が、どちらも節点を作り直さずに書き替える。**一覧の頭の一言（`#list-count`）だけは鍵に関わらず進める**（`textContent` の差し替えなので節点は消えない）
- **一覧の頭に件数（稼働中 N / 表示 N）を出さない。** 見出しの件数と同じことを言うだけになる（補足と重複をしまう）。**終了済みを上限で切ったときの「終了済み N 件は書庫へ」だけは出す**（切ったことは黙らない。`meta.endedOmitted`。行き先まで添える）
- **枠「あなたの番」は一覧のいちばん上の1つの枠**（`li.group.is-yours` > `.yours-frame`）。中は小見出し2つ（許可・質問で止まっている → 返信待ち。`groups.js` の `YOURS_GROUPS`）で、0 件の小見出しは出さない。頭は「あなたの番」（`--accent` の字）＋ 件数（`--fs-5`）＋「件」。線と面は `--accent` を `color-mix()` で薄めたもの（面は 5%。塗った面は `.btn.is-lead` の1つだけ、の約束を崩さない）。**`role="group"` は内側の器（`.yours-frame`）に付ける** … `<li>` に付けると `<ul>` の子が項目でなくなり、一覧としての読み上げが崩れる。名前は頭の `h2`（件数ごと）から `aria-labelledby` で引く。**中の小見出しは sticky にしない** … 枠は短いうえ、列いっぱいへ広げる負 margin と面が枠の線をはみ出す。**見出しの字の位置は通常の見出しと同じ式**（入れ物の内側の縁から `--list-pad` ＋ `--group-head-x`。枠の中は枠の余白 `--yours-pad-x` を差し引いて padding に置く）。値を手で足し算して書き写さない

  - **閉じたときは帯を残さない。** ボタンは詳細ペインの左上に乗るので、**その下に来る最上段だけ**（詳細の頭。頭が無いときは入力欄）をボタンのぶん右へ寄せる。タブと本文（流れる箱）は寄せない（ボタンの下に来ないので、寄せると左端が段ごとに食い違うだけ）。指定は `.deck` の中に絞る … 拡大するとペインは `.app` の外の `<dialog>` へ運ばれ、そこにはボタンが無い

- **引き出しの中の × は狭い窓だけ。** 狭い窓の引き出しは窓の左上から手前に重なって作業台の左上の開閉ボタンを覆うので、中から閉じる口が要る（`narrow.css` が出す）。広い窓の一覧は列で、開閉ボタンが隠れないので出さない（同じことをする口が2つ並ぶ）。**狭い窓では引き出しの頭の左を空けない**（ボタンは引き出しの下に隠れているので、空けると何も無い隙間になる）。**詳細の最上段は、引き出しを開けていても閉じていても寄せたまま** … ボタンは引き出しの下で同じ場所に居続けるので、閉じたときだけ寄せると開け閉めのたびに膜の向こうで頭が左右に動く
- **「稼働中だけ」はチェックボックスではなく、一覧の頭の右端の「すべて｜稼働中」**（`.live-filter`。`role="group"`・`aria-label="表示するセッション"`、ボタン2つに `aria-pressed`）。状態は `store.onlyLive` の1つ（`LS.onlyLive` に覚える）で、ボタンの `aria-pressed` はその写し（旗を2つ持たない）。押したら一覧を描き直し、選んでいた行が見えなくなったら見えている先頭へ移す（`main.js` の `setOnlyLive`）。押している側をもう一度押しても何もしない。押せるものなので面と影で浮かせる（押している側は面 `--bg-hi`・字 `--fg`・`--sh-1`、もう片方は字 `--fg-muted`）。頭の行の並びは（開閉ボタンのぶんの空き）→ 書庫への一言（`#list-count`。`margin-left: auto` で右へ寄せる）→ 切り替え → ×（狭い窓だけ。こちらに `margin-left: auto` を持たせると空きが2つに割れて切り替えが真ん中に浮く）
- **開いた状態の正は `.app` のクラス1つ。** `#list-toggle` の `aria-expanded` と名前は `setListOpen` が付け替える（旗を2つ持たない）
- **`.deck` の列は4通りを明示して書く。** `.is-list-open .deck` と `.is-insp-open .deck` はどちらも (0,2,0) で読む順に負けるので、両方立っているときの `.is-list-open.is-insp-open .deck`（0,3,0）が要る（`.is-archive.is-insp-open` と同じ形）。狭い窓では `narrow.css` がこの4通りすべてを2列へ落とす（一覧が in-flow から外れるので、列が残ると空の列が居座る）。**子と列の数は開閉のどの組み合わせでも釣り合う**（一覧・詳細・右のレールで 3/3、インスペクタを開くと 4/4）
- **読む幅の上限（`.detail` の 66rem）は面の側に置く。** `.detail-scroll` へ置くと、sticky したタブ帯の負 margin がその幅を基準にしているので崩れる。寄せは中央（左寄せだと畳んだときに余白が右だけへ寄る）。拡大では `.zoom .detail`（0,2,0）で外す

### 左のレールと上のバー（画面の切り替え）

**どのモードにいても、「止まっているセッションの数」と「行き先」が左の同じ場所に見える。**
上のバーは「探す・起こす」だけに絞ってある。

- **レールの並びは上から** 印（`deck`。飾りなので `aria-hidden`）→ 作業台 → 書庫 → 数値 → 今日のまとめ →（空き）→ 枠の輪 → 区切り → 設定 → このアプリについて。器は `index.html`、絵は `main.js`、モードの札の名前と吹き出しは `mode.js`（`nav.js` の `MODE_LIST` から）が入れる
- **モードの名前とキーの出どころは `nav.js` の `MODE_LIST` の1つ。** `store.js` の `MODES`・`palette.js` の名前・レールの札の `aria-label` と吹き出し・上のバーの題は、どれもここから作る。`index.html` に札の名前を書き写さない
- **いまのモードの札は `aria-current="page"`。ほかの札からは属性ごと外す。** ナビゲーションなので `aria-pressed` は使わない。`role="tab"` も使わない（左の一覧が上下キーを使うので、矢印キーの契約を2つ置かない）
- **作業台の札のバッジは止まっている数（`meta.stateBlocking` が真の状態）。** 一覧の枠「あなたの番」の件数（返信待ちも入れる）とは別の数で、札の名前が「止まっているもの N 件」と言うので食い違わない。面 `--hot`・字 `--bg`（6.88:1）。数字は飾り（`aria-hidden`）で、件数は札の `aria-label` と吹き出しが言う。**0 件と「まだ meta を受け取っていない」ときはバッジを出さない。** 名前のほうは分ける ―― 0 件なら「止まっているものはありません」、受け取る前は件数の言葉を付けない（「無い」と「まだ知らない」を同じ顔にしない）。書庫・数値のあいだも動かす（`stream.js` の `apply` が `renderRailBadge()` を毎回呼ぶ）
- **数字キー `1` `2` `3` で作業台・書庫・数値へ移る。** 効かせないのは Ctrl / Meta / Alt を押しているとき・IME の変換中（`isComposing`）・焦点が入力欄（`input` `textarea` `select` と contenteditable）にあるとき・`<dialog>` が開いているとき。判断は `nav.js` の `modeOfKey`、DOM を測って渡すのは `mode.js`。いまと同じモードへのキーは何もしない（押しっぱなしで書庫を引き直さない）
- **吹き出しは `:hover` と `:focus-visible` で出す。** キーボードで来た人にも名前とキーが見える（`title` はどちらも満たさない）。改行を活かすので `white-space: pre`。**レールに `overflow` を持たせない** ―― 吹き出しはレールの外へはみ出して出るので、切ると消える
- **枠の使用率は二重の輪。外が5時間の枠、内が7日の枠。真ん中は高いほうの数（% は付けない）。** 判断は `runs.js` の `rateView` → `ringView`、組むのは `usage-chart.js` の `rateRing`。説明モーダルの凡例も同じ部品で、見本の割合も同じ `rateView` → `ringView` に通して組む（色の段や真ん中の数を凡例の側で手で組まない）
  - 片方しか読めていないときは、読めていない輪は溝だけ残して弧を描かない。**外＝5時間・内＝7日の位置の意味を動かさない**（繰り上げると読み方が崩れる）。0% は長さ 0 の弧（丸い線端で点が出る）なので、読めていない輪と見分けが付く
  - 弧の色はふだん無彩色（`--fg-muted`）、80% から `--warn`、90% から `--hot`（`RATE_WARN` / `RATE_HOT`）
  - 古い観測は弧を沈め（`opacity`）、数を `--fg-faint` へ落とす。何分前かは吹き出しが言う（**古い枠の数を今の数の顔で出さない**）
  - 真ん中の数は 12px で、「100」が内側の輪（内径 27px）に収まる。「100%」は収まらない（4字で約 30px）ので、% は吹き出しと読み上げ（`aria-label`）に付ける。高いほうは丸める前の値で比べる（弧の長さは 0〜1 に丸めてあるので、どちらも 100% を超えると取り違える）
  - 弧の長さは `stroke-dasharray` を**属性で**入れる。CSS 変数にすると `test/screen.test.mjs` の `FROM_JS` に足す口が増える
  - **器の大きさは CSS が持ち、SVG は `viewBox` だけを持つ**（`.rate-ring` は `--navrail-cell`、絵は器いっぱい）。`usage-chart.js` の `RING` は viewBox の座標で、いまは 44 四方＝1 単位 1px
  - **枠は表示の字で探さない。** `rateView` は枠を `five` / `seven` の鍵で持ち、それぞれに丸める前の値（`value`）・弧の長さ（`ratio`）・字（`text`）・色の段（`tone`）を入れる。字（「5h」など）で探し直したり、字から数を読み戻したりすると、字を変えた日に輪が黙って壊れる
  - `rateView()` が null（この画面から起こした実行が1本も無い）なら輪ごと出さない。押せないので `role="img"` で、焦点は受けない（吹き出しは触れたときだけ）
- **上のバーの並びは** 題（いまのモード名）→ 接続の札 → 探す欄 →（空き）→ 再読み込み → 起こす。更新の帯（`#update`）は上のバーの中で折り返して自分の行を取る。**一覧の開閉は上のバーに置かない**（作業台の左上。「触るときに壊してはいけないこと」の一覧の開閉の項）
- **題は `--fs-4`。** 読む面の題（`--fs-5`）より1段下げる。作業台では詳細の題がすぐ下に来るので、同じ大きさだと2つの題が目を取り合う
- **探す欄はボタン。** 押すとパレット（Ctrl+K と同じもの）が開く（`palette.js` の `openPalette`）。打つ場所はパレットの中。入力欄の顔（`--bg-sunk` ＋ 細い枠）にして、Ctrl+K を知らない人への看板も兼ねる。キーの札は `palette.css` の `.kbd` を借りる。クラス名は `.topbar-find`（上のバーの部品は `topbar-` で始める。`.cmd` のような短い名前はほかの部品とぶつかりやすい）
- **接続の札はつながっているあいだ（`on`）と立ち上がり（`wait`）は出さない。** 出すのは切れたとき（`off`）と更新中（`upd`）だけ。同じことを言い続ける札は読まれなくなる。出し入れは `base.css` が `data-live` で決め、`stream.js` は何を言うかだけを持つ
- **版を上のバーに出さない。** 版は説明モーダルの「この版について」が持つ（出どころ `/api/update` の `current`）
- **狭い窓（860px 以下）ではレールを画面の下の横帯にする**（`position: fixed`・`z-index: 25`）。隠すのは印・空き・区切りと吹き出しだけ。**設定・このアプリについて・枠の輪は出す** ―― パレットに設定と説明の入口が無いので、隠すと狭い窓で設定に辿り着けない。帯のぶん `.app` の下に余白を取る（帯の高さと余白は `--navrail-bar` の1つ）。引き出し（40）と膜（30）は帯より上に重なり、下から出る紙（`.insp`）は `.deck` の中＝余白より上に居るので帯と重ならない。上のバーの探す欄は絵だけになる
- **札・印・枠の輪の器は `--navrail-cell`（2.75rem）の1つ。** 説明モーダルの凡例の輪も同じ大きさで使うので `:root` に置く
- **レールの絵は 20px で描き、線を 1.5px に揃え直す**（`.navrail .icon { stroke-width: 1.2 }`）。そのままだと線も 1.25 倍に太り、16px の絵と並んだときに重さが揃わない。**頭の印だけ 24px**（押せる札ではなく看板なので、札と同じ大きさだと並びの先頭が札の1枚に見える）で、線は `stroke-width: 1` で同じ 1.5px に戻す。**作業台の絵はモックの形（枠＋縦の仕切り1本）にしない** ―― 作業台の左上の一覧の開閉（`sidebar`）とほぼ同じ絵になり、同じ画面に並ぶ2つが同じ形で別のことをする。上に横の仕切りを1本足して「この画面そのもの」に寄せてある
- **今日のまとめの入口は2つ**（レールの `#today-open` と書庫の頭の `#archive-today`）。同じことをする口なので同じ絵（`today`）にする。配線は `today.js` の1箇所

### 数値画面（横断モードと詳細ペイン）

弾ごとに直した記録。**どれも「全幅の器」でだけ起きていた**ことに注意する
（詳細ペインは中央ペインの幅なので、同じ症状が出ない）。

- **`.usage-pane` の床は `--bg`。** ここを宣言しないと地は `body` の `--bg-sunk` になり、`.bar-track` と `.trend-spark` が敷いている同じ色と重なって**溝と折れ線の器が消える**（実測。「棒が短いときでも『ここが全体』と分かるように薄く敷いておく」というコメントが横断側でだけ効いていなかった）。`shareBar` の「残りは溝で示す」もこの床の上でしか成立しない
- **器の `padding-top` を戻さない。** 上の余白は最初の子（`.usage-pane > :first-child`）が持つ。器に持たせると、sticky した節見出しの帯（`top: 0` で padding box の上端に貼り付く）との間にその余白ぶんの隙間が残り、**スクロール中の中身がそこを通って見える**（実測 11px）
- **節の境に線を引かない。帯が境を示す。** 境を実線にする案を試したが、帯の下線との2本が 20px の間に並んで**入れ子の箱に見えた**（実測）。線は1種類（節の中の破線）だけ残して、役割を1対1にする
- **節見出しの帯は横断側だけ（`.is-usage` で絞る）。** 詳細ペインは `.panel` が既に階層を持っていて、そこへ帯を足すと「パネルの中にパネル」に戻る。あちらは帯を持たないぶん破線の境が要る
- **帯の面は視覚のためではなく、sticky で下が透けないために敷く。** 一覧の `.group-head` は沈んだ地の上で `--bg` を敷いて立たせているが、こちらは床そのものを `--bg` へ上げたので同じ手が使えない。見た目の区別は下線と太字が持つ
- **`.bar` は棒も折れ線も同じ5列。** 前は棒が4列（2列目 `1fr`）で折れ線だけ5列に組み替えてあり、両方が交互に来るスキルの節で行の形が揃わなかった。寄せる先が折れ線側なのは、あちらが実測で決めた値だから（2列目 `14rem` は器の高さ `1.5rem` に対して 9.3:1。全幅では 48:1 まで伸びて形が消えた）。**棒の側も上限を持つので、全幅で伸びきる問題が同時に解ける**
- **但し書きは1本も減らさない。** 消すのではなく `.usage-read`（`.settings-read` の借りもの）へ寄せて、面で「読めるが目立たない」段を作る。**上限は面の側に置く** … 中の `p` だけに掛けると、字は 46rem で折り返すのに面だけ器の端まで伸びて帯に見える（実測）
- **`readNote` は1本も残らなければ `null` を返す。** 空の面を置かない
- **畳むのは絵だけ。** 「残り N 件の推移を見る」（`foldBlock`）の中に入れるのは折れ線だけで、注記も表も畳まない。何が省かれたかは畳みの外に残る。並べ替えもしない（棒と絵で順位が食い違うと、同じ節に2つの順序ができる）
- **`foldBlock` と `tableDetails` を1本にまとめない。** あちらは「絵に添える表」で、表を畳むのと絵そのものを畳むのは別の判断。まとめると片方の口に `head` や `rows` を `null` で渡せる抜け道ができる
- **「全 N 件を表で見る」を3つ並べない。** 区別が N の値だけになり、閉じたままではどれがどの表か分からない。中身の名前を入れる（`tableDetails` の第1引数は文字列なので署名は変えずに直せる）
- **無帰属（`shareBar`）をスキルの棒より先に置く。** 実測で全体の 5〜8 割がどのスキルにも紐づかないので、それを言わずに個別の割合だけ並べると、足しても 100% に届かない理由が読めない
- **スキルの棒は「全体に占める割合」で並べる。** 「1回あたり」で並べていたのは `runs` が呼び出し回数だった頃の話で、いまは「使ったセッション数」なので `avg` の意味が変わっている。割合なら、たまたま重い1回が順位を歪めることもない（**母数での足切り（`RANK_MIN_RUNS`）も落とした** … 1本でしか使っていないスキルが実際に重いことは普通にある）
- **`barList` の `value` は長さ、`text` は読ませるため。** 割合のように単位が違うものは `text` で渡す。1つの値に2つの役目を持たせない
- **詳細ペイン側で「呼んだ回数」「1回あたり」を出さない。** 1本の会話ではラベルが途切れて再開する例が実測0件なので、`runs` は常に 1、`avg === ite` になる（＝情報がゼロ）。この会話に占める割合へ差し替える
- **サブエージェントのスキル別は、親の `skills` に足し込まない。** `Task` を1回投げただけの会話が機械的に上位へ来る。分母も子ぶんの合計にして、別の節として読ませる
- **`deltaText` は 1000% を超えたら倍率（`×98`）へ替える。** 「+9687%」は事実だが桁を数えないと読めない（実測：セッションを跨いだ推移で 1本目 70k → 直近 6.9M）。**符号は付けない** … 減った側は比が 1 を超えないので、倍率が出た時点で必ず増加。`+×99` のように印を2つ重ねない
- **`usage.css` のコメントに文を足すときは、閉じ `*/` の位置を確かめる。** 既存ブロックの直前に書き足して `*/` を残したまま新しい文を置くと、そこから次のルールまでがセレクタとして読まれ、**ルールが丸ごと無効になる**（実測で `.usage-pane` の床も padding も効かなくなり、`getComputedStyle` の `backgroundColor` が `rgba(0,0,0,0)` になっていた）
- **節の出し分けは CSS が `data-sec` でやる。** JS は器に名前を書いて `aria-pressed` を替えるだけ（`settings.css` の `.settings-pane` と同じ作法）。**節を1つ足しても配線が増えない**し、節点を作り直さないので開いた `<details>` も閉じない。節の一覧は `SECTIONS` の1行で足せる
- **節ナビの見た目を新しく作らない。** `list.css` の `.tab`（下線式）を借りる。**前は `settings.css` の `.settings-navb` だった** … 「沈んだ帯（`--bg-sunk`）の上で選んだものが `--bg` の面へ浮く」関係がそのまま成り立つ、という理由で。関係そのものは確かに成り立っていたが、**あれは縦ナビの作法**（選んだものの左に `--accent` の棒）で、横に並ぶ帯で使っているのは画面でここ1箇所だけだった。おかげでタブの顔が3種（`.tab` / `.detail-tab` / ここ）になっていた。`.tab` に寄せると2種に減る ―― **中央のタブ帯（`.detail-tabs`）も同じ `--bg-sunk` の地の上で下線式**なので、前例がそのまま使える。件数（`.n`）だけはこちらで沈める
- **`.usage-nav` に `flex-wrap` を持たせる。** `.usage-head` は折り返すが、その中の `.usage-nav` は別の flex コンテナなので自分で畳まないと横へ溢れる（実測では 360px でも4札が1行に収まったが、札を1つ足せば当たる）
- **開くたび概要へ戻す。** 節を `localStorage` に残さない（モードと同じ扱い。設定モーダルが「開くたびに畳んだ状態へ戻す」のと同じ理由 … 前に開いたかどうかを覚えると、開くたびに違う画面が出る）。節を替えたら `scrollTop` も戻す（前の節の位置が残ると、短い節へ移ったときに何も見えない位置で止まる）
- **概要の札の差は、読んだ窓の中の新旧で比べる**（`usage-trend.js` の `halfTrend`）。応答には読んだ本数より前のセッションが無く、前の窓も読むと全文を読む量が倍になる（実測 459ms）うえ、60 本を選ぶと走査の上限（60）を超える。**時刻（`mtimeMs`）で並べ替えてから割る** … 応答の `rows` は実消費の多い順なので、そのまま割ると「重い半分と軽い半分」になる。奇数なら真ん中を外して本数を揃える。札には短く「古い N 本より ±x%」、比べ方の説明は下の注記に1回だけ。**差に色を付けない**（`deltaText` の約束どおり。多いのは長く働いた日かもしれない）。**命中率は差を出さず線だけ** … 行から半分ぶんの命中率を正しく組み直すには入力トークンの内訳が要る
- **概要の「この期間の内訳」と「いちばん重いもの」は2列**（`.usage-two`。器の幅で折り返す。下限 26rem）。縦に積むと全幅の器で右半分が空いていた
- **概要の「いちばん重いもの」は、行ごとに何で並べているかを書く。** ツールは文脈への積み上がり、スキルは全体に占める割合、セッションは実消費で、**1画面に3つのものさしが混ざる**。書かないと同じ順序で並んでいると読まれる
- **`.usage-head` の `select` に `cursor: pointer` をここだけ足さない。** `<select>` のネイティブ既定が `default` で、書庫（`.archive-head select`）も同じ値を持っている。数値画面だけ変えると、同じ見た目の2つの帯で挙動が食い違う
- **絞り込みの札は書庫の `.archive-field` を借りる。書き写さない。** 前は `usage-mode.css` に `select` の見た目を写してあり、「同じ宣言をこちらに持つほうが、どちらの都合で変えたのかが後から読める」と理由まで付けてあった。**その理由のほうが実態と合わなくなった** … 写した結果、書庫の札には絵と枠と外す口があるのに、数値の帯だけ素の `<select>` が3つで**絵が1つも無い**状態になっていた。「30本」だけを見ても、それが期間なのか本数なのか形からは出てこない。借りられるのは、あちらのセレクタが `.archive-head` を親に取っていないクラス単体だから（`archive.css` は `usage-mode.css` より前に読まれるので順の心配も要らない）
- **件数（`#usage-count`）を帯の3行目に落とさない。** あれは絞り込みの結果の説明なので、絞り込みと同じ行の右端に置く（`margin-left: auto`。一覧の `#list-count` と同じ作法）。`flex: 1 0 100%` にすると、節ナビ・絞り込み・件数で帯が3行を使う
- **絞り込みの既定は `USAGE_DEFAULTS`（`store.js`）の1箇所。** 起動時の値と「絞り込みを外す」で戻る先が同じものなので、2箇所に書くと片方だけ直した日に「外したのに既定へ戻らない」になる。外す口を出すかどうかの判定も、この表を舐めて作る（`limit !== 30` のように数を直に書かない）
- **`.stat` は沈めてよい。ただしそれは床が `--bg` だから。** `05bebd5` で「札を沈めると地に溶ける」と却下したのは、**ペインの地そのものが `--bg-sunk`（`base.css` の `body`）だった頃**の話。いまは `.usage-pane` の床が `--bg` へ上がっていて、`.usage-read` が同じ根拠で既に沈んだ面を使っている。床を戻すなら、この2つも一緒に見直すこと。枠は持たせない ―― 押せる `.card.is-usage`（枠＋面＋行き先の印）と止まった絵で見分けが付かなくなる
- **`.stat-label` を `--fs-0` へ戻さない。** 値が `--fs-6`（30px）なので、`--fs-0` では差が開きすぎて何の数か読まれない（`--fs-0` が 11px だった頃に決めた）。`--fs-1`（いまは 13px）まで上げてある。但し書き（`.stat-note`）は `--fs-0` のままにして、ラベルとの段を残す

### 説明モーダル（このアプリについて）

左のレールの `info` から開く。器と作法は設定モーダルと同じで、
**中身のほとんどは `index.html` に静的に置いてある**（`about.js` が組むのは凡例4つと版の1行と本文の絵だけ）。

- **凡例を画面側に書き写さない。** ここがこの節の主題。印の意味を手で並べると、**状態や種類が1つ増えた日に凡例だけが古くなる**。引く先は既にある表 …… 状態の色と形は `store.js` の `STATE_TONE`（`toneOf` / `colorOf`）、状態の日本語は `meta.stateLabels`、止まっているかは `meta.stateBlocking`、群と種類の対応は `timeline/kinds.js` の `KIND_MARK` ＋ `MARK_GROUPS`、種類の日本語は `KIND_LABELS`。**「表を2つ持たない」がそのまま効く場所**
- **形の名前（菱形・輪・塗った丸）を1文字も書かない。** 凡例には実物の点（`.state[data-s]`）をそのまま置く。形は見れば分かるし、`list.css` を直した日にここが嘘になることもない
- **状態は1つずつではなく、調子（tone）ごとに1行にする。** 形を決めているのが調子だから（`needs-answer` と `needs-approval` は同じ菱形）。同じ調子の状態は名前を並べて出す
- **印を持たない種類を凡例から落とさない。** `compact` は `KIND_MARK` に無いので、最後に「印を持たないもの」として出す。黙って落とすと、画面には出ているのに凡例に無い行が生まれる。`elided`（省略）はチップにも出さない間引きの副産物なので、こちらでも出さない
- **群の表（`MARK_GROUPS`）は `kinds.js` に置く。** 前は群の名前が `KIND_MARK` のコメントにしか無く、絞り込みの帯にも凡例にも出せなかった。`MARK_ICON` はその表から作る（手で書くと群を1つ足した日に片方だけ古くなる）
- **版を出すのはここ1箇所だけ。** `/api/update` の `current` から取る。上のバーには置かない（言うことが無い日も常に出ている札は読まれなくなる）。まだ引けていなければ名前だけ出す ―― 「不明」とは書かない（0 と不明を分けるのと同じ）
- **札の凡例（`TAGS`）だけは `about.js` が表を持つ。** `.tag.is-*` は CSS にしか無く、「どのクラスが何を意味するか」を持っている場所が他に無いため。増やすときは `list.css` と一緒に直す
- **器の高さを設定モーダル（34rem）に合わせない。** あちらは「節ごとに中身の量が違うので、いちばん多い節に合わせて固定する」で 34rem。こちらは節がどれも読み物で、印の節がいちばん縦に長い。34rem のままだと凡例が常にスクロールの向こうへ隠れる（`38rem`）。**`max-height` にしない**のはあちらと同じ理由
- **足の1行（`~/.claude` は読むだけです）を節の中へ入れない。** 会話ログを扱う道具なので、渡された人がいちばん先に気にする。節を移っても消えない場所に置く
- **アプリ全体を「読み取り専用」と言わない。** 長く足に「読み取り専用で動いています」と書いていたが、起こす・答える・ピンとメモを足してから事実と合わなくなっていた（2026-10-15 に見直した）。正しく言えるのは「`~/.claude` は読むだけ」と「自分で書くのは `%LOCALAPPDATA%\ClaudeDeck\` の下だけ」の2つ。起こしたセッションで書くのは Claude Code 本人、入れた版は Windows に3つ登録する（自動起動・通知の差出人・`claude-deck://`）、まで書く
- **機能を足したら「できること」の節にも1つ足す。** 説明が「モード3つ」のまま、通知・ピンとメモ・今日のまとめがどこにも書かれていなかった。見出しの絵は `data-icon` で、`about.js` が1回だけ差す
- **枠の輪の凡例の割合を書き写さない。** 何 % で色が変わるかは `runs.js` の `RATE_WARN` / `RATE_HOT` から `fillMeters()` が組む。見本の輪は左のレールと同じ部品（`usage-chart.js` の `rateRing`）で、見本の割合もレールと同じ `rateView` → `ringView` に通す（段の割り当てを凡例で手書きしない）
- **キー操作を画面のどこかに1回は出す。** <kbd>Ctrl</kbd>＋<kbd>K</kbd> は知らないと一生使われないのに、いままで画面のどこにも書いていなかった。数字キー（1・2・3）もここに並べる（レールの吹き出しにも添えてあるが、触らないと出ない）
