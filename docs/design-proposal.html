DESIGN PROPOSAL

のっぺりの正体は
「段」がひとつも無いこと。

色のセンスの話ではない。字も影も角丸も余白も、いまはほぼ単一の値で組まれていて、 差を作る手段が 1px の罫線しか残っていない。 ここでは段（スケール）を作り直したうえで、画面の主役を何に置くかまで 違えた3つの案を並べる。上の A B C （または 1 2 3）で全部のモックが一斉に切り替わる。

023案に共通する土台

案の性格は違っても、直す道具は同じ。単一値になっているものに段を作る。 以下はいま選んでいる案の実際の値で描いてある。

字の段 ―― 7段に割る

いまは 10.9〜14.1px の 3.2px 幅に 88% が固まっている。ここを 7 段に割り、 いちばん知りたい数（経過時間・トークン数・件数）に大きい段を回す。 字を大きくするのではなく、大きい字と小さい字の両方を作るのがねらい。

--fs-7402.4M
--fs-6286分12秒
--fs-520請求書の取り込みバッチを日次に切り替える
--fs-415本文。長い Markdown を読む段
--fs-313カードの題・時系列の本文
--fs-212状態の名前・タブ・ボタン
--fs-111添え物（置き場所・件数・いつ測ったか）

面と影の段 ―― 4段に割る

いまは「地」と「浮きもの」の2段しかない。間に2段入れると、 同じ1px の枠のままでもカードが紙に見える。 --hi（内側の1pxのハイライト）は影を落とさずに面を持ち上げる道具で、 暗い配色でとくに効く。

0沈んだ面・帯
--sh-1カード・ボタン
--sh-2選択中・浮いた札
--sh-3モーダル・拡大

角丸の段 ―― 役割で持つ

実質1段（8px）なので、押せるものと読むものが同じ硬さで並ぶ。 小さいものほど角を立て、大きい器ほど丸める。 ピル（999px）は押せるものだけに残す。

--r-sm札・入力欄
--r-mdカード・パネル
--r-lgモーダル・ヒーロー
--r-pill押せる札だけ

差し色の使い方 ―― 面をひとつだけ許す

いまは --accent を線と字にしか使っていない（.btn.is-lead も面を塗らない）。 そのぶん画面のどこにも「いちばん強い場所」が無い。 1画面に1つだけ、塗った面を置く。 状態色（止まっている・待っている）はいままで通り面を塗らないので、優劣の読み方は壊れない。

accent accent-soft hot warn calm done off bg elev sunk hi
simplify main つながっている

動き ―― 130ms だけ

いまは border-color .12s がほぼ全部。 触ったときに 1px 浮かせるのと、 止まっているものの点だけ呼吸させるの2つを足す。 それ以上は要らない。作業画面なので、動くものが多いと状態の変化に気づけなくなる。 prefers-reduced-motion は既に効いているので、ただ乗りできる。

05既存の約束とぶつかる所

白紙で描いた。その結果 public/CLAUDE.md の「触るときに壊してはいけないこと（画面側）」に ぶつかった所を全部出す。ぶつかったから直す、ではない。 あの約束はどれも実測から来ているので、緩めるなら同じ強さの理由が要る。

いまの約束この案は理由と、代わりに置くもの
状態色は点と細いバーだけ。面は塗らない 守る 状態色の面は1つも塗っていない。塗ったのは --accent（起こす・送る・許可する）だけで、あれは状態色ではない。優劣の読み方は変わらない
.btn.is-lead は面を塗らない 壊す ここは変える。 元の理由は「上のバーでいちばん強い面がボタンになる」だが、そもそも画面のどこにも強い面が無いのが今回の問題。1画面に1つだけという条件を付けて塗る
ピル型（999px）は押せるものだけの形 守る ピルは書庫の絞り込みの札と .composer-now だけ。.tally と .rate は面も枠も持たないまま
押せる／押せないを、動かさないと出ない差で表さない 守る 押せるもの＝浮いた面＋影（--sh-1 と --hi）、押せないもの＝沈んだ面・影なし。止まった絵で見分けが付く
急ぎの印を新しい色で作らない 緩める 色は増やさない（--hot のまま）が、光の輪（color-mix で --hot から作る）を足す。新しいトークンは増えないので、明暗の二重定義を両方直す義務は生まれない
破線は但し書きと区切り専用 守る 破線を使ったのは書庫の「まだ届いていない数値の器」だけ。あれは但し書きの側
新しい色トークンを足さない（明暗の二重定義が増える） 緩める 足すのは --bg-hi と --accent-soft の2つだけ。それ以外の派生（光の輪・棒のグラデ・パネルの薄い面）は color-mix() で既存トークンから作るので、定義は増えない
アイコンを絵文字にしない。形は icons.js の1箇所 守る モックはインライン SVG の <use>。実装時は icons.js に形を足すだけで済む
innerHTML を使わない 守る 案の中身はほぼ CSS。増える DOM はヒーロー帯（案A）とストリップ（案C）で、どちらも el() で組める
見出しの段は「大きさ・上の余白・線の太さ」で付ける 守る markdown.css の実測値（h1 18.88px …）はそのまま。本文の段（--fs-4）を上げる案Bだけ、比率を保って全段を再計算する
一覧で並べ替えない（順はサーバーが決める） 守る 案Aのヒーロー帯は並べ替えではなく切り出し。row.blocking が真のものを先頭から取るだけで、比較器は増えない
「あなたの番」の見出しは 0 件でも残す 緩める 案Aはヒーロー帯が 0 件のとき帯ごと消える。代わりに一覧側の見出しは 0 件でも残すので、「見ていない」と「無い」の区別は付いたまま
状態の点を自前で描かない（.state::before がすでに描く） 守る 案Bの「形で分ける」も .state::before の border-radius と box-shadow を替えるだけ。要素は増やさない
案Bだけ、追加で1つ判断が要る。 強調色をテラコッタにすると、--hot（あなたの操作で止まっている）と色相が近くなる。 tokens.css のコメントが「Claude の terracotta にすると --d-hot と見分けが付かなくなる」と 書いて避けた所そのもの。案Bはそれを色ではなく形で解く ―― hot は菱形、warn は輪、off は白抜きの丸。 案Bを選ぶなら、この形の割り当てもセットで入る。

06決まったあと、どう当てるか

どの案でも段の切り方は同じなので、前半は案が決まる前でも当てられる。 骨格を変えるのは最後の段だけ。

段やること触る場所効き方
1 段のトークンを足す（字7段・影3段・角丸4段・--bg-hi・--accent-soft） tokens.css 足すだけ。この時点では何も見た目が変わらない
2 面と影の段を当てる（カード・パネル・ボタン・モーダル） base.css list.css detail.css ここでいちばん印象が変わる。 骨格は1行も動かない
3 字の段を割り当て直す（経過時間・トークン数・件数を大きく） list.css usage.css detail.css 25種のばらけた font-size を7段へ寄せる。差分は大きいが機械的
4 触ったときの手応え（1px 浮く・光の輪・点の呼吸） base.css list.css prefers-reduced-motion は既に効いているのでただ乗り
5 骨格を変える（案Aヒーロー帯／案B版面／案C表とストリップ） list.js dom.js ＋ 新しい CSS 1枚 ここだけ JS に及ぶ。 案が決まらないと着手できない
  • 1〜4 だけでも「のっぺり」はほぼ解ける。 骨格の話（5）は情報設計の好みなので、分けて決められる
  • 新しい CSS を1枚足すときは index.html の <link> の順に気をつける（宣言順で勝ち負けが付く。narrow.css は必ず最後）
  • test/contract.test.mjs は色も寸法も見ていないので、この変更で落ちるテストは無い見込み
次に決めることは2つ。①トークン（色と質感）をどれにするか ②骨格をどれにするか。 この2つは独立に選べる（「案Bの色で案Aの骨格」も成立する）。
