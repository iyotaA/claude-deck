SETUP GUIDE

Slack の Incoming Webhook を作る

ClaudeDeck が「あなたの返事待ち」を Slack へ飛ばすための下準備です。 Slack 側に送り先をひとつ作り、その URL を控えるところまでを説明します。

  • 対象ClaudeDeck の通知機能
  • 作成日2026-08-06
  • 所要10 分ほど

01この手順は何か

ClaudeDeck は、待っているセッションを一覧で見せる画面です。 ただし見るには画面を開いている必要があります。

席を外しているあいだにセッションが質問を出して止まると、戻るまで誰も気づきません。 そこで Slack へ通知を飛ばします。

Incoming Webhook とは

Slack が発行する、投函口の住所のようなものです。 郵便受けの住所を知っている人は誰でも投げ込めます。

逆向きには使えません。 この URL から Slack の中を読むことはできません。

安心してよいこと

一方通行なので、Slack 側から手元のパソコンをのぞかれることはありません。 ClaudeDeck が外へ出す通信も、この投函口への送信だけです。

要るもの

  • Slack ワークスペースのアカウント
  • ブラウザ
  • 通知を受け取るチャンネル、または自分あての DM

02Webhook を作る

  1. Step 1 api.slack.com/apps を開く Slack にログインしているブラウザで開きます。
  2. Step 2 Create New App から From scratch を選ぶ 名前は ClaudeDeck などで構いません。使うワークスペースも選びます。
  3. Step 3 左メニューの Incoming Webhooks を開き、スイッチを On にする 既定では Off です。On にしないと次のボタンが出ません。
  4. Step 4 Add New Webhook to Workspace を押す 投稿先のチャンネルを選んで Allow を押します。
  5. Step 5 表示された URL をコピーする https://hooks.slack.com/services/ ではじまる長い文字列です。
チャンネルはあとから変えられません

Webhook 1 本につき、投稿先はひとつに固定されます。 別のチャンネルへ送りたくなったら、Step 4 からもう 1 本作ります。

最初にどこへ送るかを決めてから進めてください。 決め方は次の節にあります。

03送り先をどこにするか

通知には、Claude から聞かれた質問の本文がそのまま流れます。 つまり業務の中身が見える場所に置くことになります。

送り先向き理由
自分だけの private チャンネル おすすめ ほかの人に見えません。あとから見返せます。チャンネル単位で通知の強さを変えられます。
自分あての DM 使える 作る手間がかかりません。ただし DM 一覧に埋もれやすく、あとから探しにくくなります。
チームの共有チャンネル やめる 質問の本文が全員に流れます。自分あての通知でもあるので、まわりにも通知が飛びます。

private チャンネルを新しく作る場合は、Slack で「新規チャンネル」から作ります。 名前は my-claude のように、自分だけが分かるもので構いません。

会社の Slack では止められることがあります

アプリの作成が管理者の承認制になっている場合があります。 Step 2 で先へ進めないときは、この設定が原因です。

その場合は管理者に申請します。 詳しくは 08 の「詰まったとき」を見てください。

04動くかどうか確かめる

URL を控えたら、その場で送れるか試します。 PowerShell に次を貼り付けてください。 

$url = 'ここに Step 5 でコピーした URL を貼る'
$body = [System.Text.Encoding]::UTF8.GetBytes('{"text":"ClaudeDeck テスト"}')
Invoke-RestMethod -Uri $url -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
成功したとき

画面に ok とだけ返り、Slack のチャンネルに「ClaudeDeck テスト」が届きます。 これで Slack 側の準備は終わりです。

なぜ本文をバイト列にしているのか

文字列のまま渡すと、PowerShell の版によっては日本語が化けて届きます。 UTF-8 のバイト列に直してから渡すと、どの版でも同じ結果になります。

うまくいかないときの返り値は 08 にまとめてあります。

05スマホに届くようにする

Webhook を作っただけでは、スマホが鳴るとは限りません。 Slack 側の通知設定が別にあるためです。

席を外しているときに気づくのが目的なので、ここも合わせて確認します。

  • チャンネルの通知を「すべての新規メッセージ」にする
  • スマホの Slack アプリで通知を許可する
  • おやすみモードの時間帯を確認する
  • パソコンを使っているあいだはモバイル通知を止める設定を切る

最後のひとつは見落としやすい項目です。 Slack の既定では、パソコンで操作しているあいだスマホへ送りません。

席を立った直後に届いてほしいので、この設定は短めにしておきます。 Slack の設定から「通知」を開き、モバイルへ送るまでの待ち時間を変えられます。

06URL の扱い

この URL は鍵そのものです

ユーザー名もパスワードもありません。 URL を知っている人は、誰でもそのチャンネルへ好きな内容を投稿できます。

守ることは 4 つです。

  • チャットに貼らない。Claude に相談するときも貼らない
  • Git にコミットしない。設定ファイルは .gitignore の外に置かない
  • スクリーンショットに写さない
  • 人に渡さない。必要なら相手に自分の分を作ってもらう

ClaudeDeck の画面では伏せますが、ログには残ります

ClaudeDeck は原文を返す口で、この形の URL を「（伏せました）」に置き換えます。 ただしこれは画面に出さないだけの処理です。

Claude Code の会話ログそのものには、貼った文字がそのまま残ります。 だから貼らないことが対策になります。

もし漏らしてしまったとき

古い Webhook を消せば、その URL は使えなくなります。 api.slack.com/apps から作ったアプリを開き、Incoming Webhooks の一覧で削除します。

そのあと Step 4 から作り直し、新しい URL に差し替えます。

07ClaudeDeck 側の設定

通知の本体はまだ入っていません

この節に書いた設定は、通知機能の実装が入ってから有効になります。 いま設定しても害はありませんが、まだ何も飛びません。

設定の入れ方は 2 通りあります。 環境変数が優先で、無ければ設定ファイルを読みます。

環境変数で入れる

setx CLAUDE_DECK_SLACK_WEBHOOK "コピーした URL"

setx は次に開いたウィンドウから効きます。 自動起動しているサーバーには届かないので、いちど終了させて起動し直します。

設定ファイルで入れる

置き場所は %LOCALAPPDATA%\ClaudeDeck\config.json です。 自動起動のログと同じフォルダになります。 

{
  "notify": {
    "slackWebhookUrl": "コピーした URL",
    "settleSec": 6,
    "remindMin": 0,
    "detail": "full"
  }
}
キー既定意味
slackWebhookUrlなしWebhook の URL。これが入っているときだけ通知が動きます。
settleSec6待ちに入ってから送るまでの秒数。目の前にいてすぐ答えた分は送りません。
remindMin0放置したときの再通知までの分。0 で無効です。
detailfullnone にすると質問の本文を落とし、状態だけ送ります。

効いているかを見る

設定したのに動かない、という事故がいちばん起きやすい場所です。 次の口で確かめられます。 

curl http://127.0.0.1:4317/api/health

返ってくる中身の notify.enabled が true になっていれば読めています。 URL は伏せた形でしか出ません。

08詰まったとき

Create New App が押せない。作っても承認待ちになる

会社のワークスペースでは、アプリの追加が管理者の承認制になっていることがあります。 この場合は自分だけでは進められません。

申請するときは、次を添えると通りやすくなります。

  • 用途は自分あての通知だけであること
  • 投稿先は自分の private チャンネル 1 つに限ること
  • Incoming Webhook は投稿専用で、Slack の中を読む権限を持たないこと
投稿先のチャンネルを変えたい

既存の Webhook の投稿先は変えられません。 Step 4 の Add New Webhook to Workspace からもう 1 本作り、新しい URL に差し替えます。

古いほうは使わなくなるので、一覧から削除しておきます。

invalid_payload が返る

送った中身が JSON として読めていません。 引用符の対応が崩れているか、日本語が化けている可能性があります。

04 のコードをそのまま貼り直し、URL の部分だけを差し替えてください。

no_service や 404 が返る

URL が違うか、その Webhook がすでに削除されています。 コピーしたときに末尾が欠けていないかを確かめてください。

それでも直らないときは、作り直したほうが早いです。

channel_not_found が返る

投稿先のチャンネルが消えているか、アプリがそのチャンネルから外されています。 チャンネルを作り直した場合は、Webhook も作り直しになります。

社内のプロキシを通さないと外へ出られない

ClaudeDeck は外部のパッケージを使わない方針なので、プロキシには対応していません。 Node.js の fetch は HTTPS_PROXY を見ないためです。

04 のテストが失敗し、ブラウザからは Slack が見えるという場合は、これが原因の可能性があります。

テストは届いたのに、スマホが鳴らない

Slack 側の通知設定です。 05 の 4 項目をひとつずつ確かめてください。

とくに「パソコンを使っているあいだはモバイルへ送らない」の待ち時間が長いと、席を立った直後には鳴りません。

ここまでで Slack 側の準備は終わりです。 控えた URL は 07 の手順で入れ、通知の本体が入ったら 04 と同じ形で届くようになります。
