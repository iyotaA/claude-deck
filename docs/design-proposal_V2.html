信号盤の骨格に、

V1 の3案から決まった組み合わせ。ただし素朴に重ねると壊れる。 案A の骨格は密度で全体を見せる設計、案B の質感は余白で読ませる設計なので、 そのまま足すと一覧が縦に伸びて信号盤の役目が消える。 衝突は3つ出た。その解き方がこの文書の本体で、モックはその結果。

01混ぜると出る3つの衝突

どれも「どちらかを捨てる」ではなく、効く場所を分けることで両立させている。

衝突 1 ／ 密度
案B の本文 15px・行間 1.78 で一覧を組むと、信号盤にならない

案A の骨格は「ヒーローに出ないものは1行に落とす」で全体を見せる。 そこへ案B の尺をそのまま当てると、1行の高さが 28px から 47px へ増える（計算値）。12本並べると 377px が 568px になり、 スクロールしないと全体が見えない＝信号盤の役目が消える。

解き方 ―― 字の段を8つに割り、効かせる場所を分ける。 案B の7段の下に --fs-0: 11px を1つ足す。 一覧と圧縮した行は 11〜13px・行間 1.5、 詳細ペイン（読む場所）は 15px・行間 1.78。 案B の「読ませる」は本文のためのものなので、一覧まで持っていく必要が無い。

衝突 2 ／ 色
テラコッタの強調が、--hot（あなたの操作で止まっている）と近い

tokens.css のコメントが名指しで避けている所そのもの ―― 「--d-accent を Claude の terracotta にすると --d-hot と見分けが付かなくなる」。 しかも案A の骨格はヒーローカードで hot をいちばん大きく出すので、 この衝突がいちばん目立つ場所に来る。

解き方 ―― 二段構え。 ①状態色を赤系から意図的に離す（明 #A51C30 のクリムゾン／ 暗 #FF5A76 のローズ。テラコッタとは色相で約30度離れる）。 ②それでも足りないので、点の形も変える。 色覚の差にも効くし、.state::before の border-radius と box-shadow を替えるだけなので要素は1つも増えない。

あなたの番（菱形） 返信待ち（輪） 実行中（塗った丸） 終了（細い輪）
強調（テラコッタ）は押せるものにしか出ない。状態の点は必ず形を持つ。 この2つが同じ画面に並んでも、役割を取り違えない
衝突 3 ／ 形
案B の角丸 18px を、案A の圧縮した行に当てられない

高さ 28px の行に 18px の角丸を当てると、 丸みが上下から食い合ってカプセルになる。 しかもピル型（999px）は「押せるものだけの形」と決まっているので、 押せるが押せる札ではない行が、札の顔で並ぶことになる。 逆にヒーローカードの左帯（3px）は、 18px の角丸だと上下の端が丸みに飲まれて消える。

解き方 ―― 角丸を5段にして、役割で持つ。 小さいものほど角を立てる。行は --r-sm（8px）、カードは --r-md（12px）、 ヒーローとモーダルだけ --r-lg（18px）。 ヒーローの左帯は 3px → 4px に太らせる（丸みに負けない太さ）。

--r-md 12pxカード・パネル

05決めたこと／まだ決めていないこと

決まったこと

論点決めたこと理由
ヒーロー帯のボタン 答えられるものだけボタンを出す（外のセッションは「ターミナルを前面に」） asks は run/ledger.mjs の行にしか載らない ＝ 外で走っているものは答える窓口が存在しない。混在するので、差を「この画面から」の札で示す

明るいほうの字の濃さ AA（4.5:1）を満たすまで押し上げる 最初の案は --fg-faint が 2.92。いまの本体と同等なので退行ではないが、トークンを作り直すここが直す機会。3段の差は保てる
圧縮行の中身 点・題・経過だけ 1行 28px を保つ。置き場所やスキルは、選んだときに詳細ペインで読める
時系列の印 入れる。ただし 5群に丸める（16 ある kind ごとには割らない） 種類の名前は隣に字で出ているので、印は「読み飛ばすため」に割れば足りる。13px の丸に16種類を描き分けるのは無理がある。新しいアイコンは3つで済む

実装のときに踏みそうな所

  • 新しい CSS を足すなら <link> の順に気をつける。 宣言順で勝ち負けが付き、narrow.css は必ず最後。ヒーロー帯の CSS は list.css の直後が自然
  • ヒーロー帯を .app の直下に置かない。 grid-template-rows が2行しか宣言していないので、3つ目の子を足すと高さの配分が崩れる。.topbar の中に flex: 0 0 100% で置くか、.deck の中の1行として持つ
  • [hidden] で出し入れするものに display を素で書かない。 ヒーロー帯は 0件で消えるので、display: grid を素で書くと [hidden]（0,1,0）に勝って出たままになる
  • 0件の1行（.hero-none）を消さない。 帯ごと消すだけだと、その場所に何があったのか分からなくなる
  • 帯を renderList() の中で毎回組み直さない。 あれは dom.list.replaceChildren() で丸ごと作り直し、stream.js が2秒ごとに呼ぶ。素朴に足すと横に送った位置が毎回先頭へ戻る ―― 「ほか N 件」を見に行った瞬間に引き戻される。blocking な行の id と状態の並びを鍵にして、変わったときだけ組み直す（detailKeyOf() と同じ作法）
  • refreshTimes() の対象に帯を足す。 いまは dom.list.querySelectorAll('.card') しか見ていないので、帯の .h-idle（6:12）が固まったままになる。上の「鍵が変わるまで組み直さない」とセットで必要（組み直さない以上、時刻は中身だけ差し替えるしかない）
  • 膜は帯（スクロールする側）ではなく器に載せる。 中に置くと膜も一緒に流れて、いつも同じ場所に居てくれない
  • 膜の出し入れは data-edge の1語に畳む。 判断は scroll を見る側に置き、CSS は当てるだけにする。両方に散らすと、どちらで決めているのか追えなくなる。resize でも引き直す（窓幅で「そもそも溢れているか」が変わる）
  • 札の幅を 1fr で分けない。 2件のときに2枚で埋まり、「まだ続きがある」が伝わらなくなる。固定幅（min(21rem, 74%)）にして必ず次を見切れさせる
  • 答えられないセッションに「許可する」を出さない。 asks は run/ledger.mjs の行にしか載らないので、外で走っているものは押しても何も起きない。判定は row.asks の有無ひとつ
  • 帯のボタンから run-view.js の節点を掴まない。 「許可して進める」の実体は run-ask.js の1枚に保つ（要求カードを2枚組むと「どちらが本物か」の管理が丸ごと増える）。帯のボタンはその1枚を呼び出すだけにする
  • color-mix() は Chrome 111 以降。ローカル専用の画面なので問題ないが、使えない環境向けの代替は用意していない
  • test/contract.test.mjs は色も寸法も見ていないので、この変更で落ちるテストは無い見込み
