> `src/view/` を触るときに読む。
> 全体の地図と横断の約束はルートの `CLAUDE.md` にある。

`read` が読んだものを `parse` が解釈し、ここが API 応答の形に組む。
入口の名前と応答の形は変えない（一覧は `listSessions`、詳細は `getSessionDetail`）。

一覧と詳細で同じ項目（`name` や `project` など）は `view/shape.mjs` が組む。
以前は両方が別々に組んでいて、片方だけにフォールバックが付いている状態になっていた。

**`permissionMode` を `deriveState` へ渡すのは、呼ぶ側（ここ）の仕事。**
`state.mjs` から `meta.mjs` を import すると `parse` の中に新しい辺ができるので、
`sessions.mjs` と `detail.mjs` が `extractMeta` の結果から1項目だけ抜いて渡す。
**`extractMeta` → `deriveState` の順を崩さない**（もう meta を組んでいるので追加の走査は0）。
**`meta` ごと渡さない**（理由は `src/parse/CLAUDE.md`）。

一覧は末尾64KB、詳細は全文を読むので、`permissionMode` の見え方は食い違いうる
（モードを途中で替えたセッションで、一覧が新しい値・詳細が最初の値を見る）。
画面では `public/js/rows.js` の `LIVE_FIELDS` が一覧の状態を正にしているので、
食い違っても左のカードと右のヘッダは揃う。

`summarizeRows()` の `needsYou` は `row.blocking === true` だけを数える。
**`ball === 'master'` で数えない**（返信待ちが混ざって、「あなた待ち」の数が
「いま手を止めている件数」ではなくなる）。判断は `parse/state.mjs` の `isBlocking` が持ち、
ここは配るだけ。`=== true` で見るのは、台帳側（`run/ledger.mjs`）が項目を足し忘れた将来でも
`undefined` を「数えない」に倒して落ちないため。`needsYou` を読むのは `cli.mjs`（「あなた待ち N」）だけ。
画面の左のレールのバッジは `meta.counts` と `meta.stateBlocking` から数え直している
（`public/js/nav.js` の `blockingCount`。「止まっているか」の出どころは `isBlocking` と同じ `STATE_BLOCKING` の表）。

**数値（`view/usage.mjs`）の設計は `src/parse/CLAUDE.md` にある。**
集計そのものは `parse/usage.mjs` にあり、両方を1枚にまとめてあるため。
例外は次の節の境目（`meta.scanFrom`）で、これは「どれを開くか」の話なのでここに置く。

## 横断の数値の境目（`/api/usage` の `meta.scanFrom`）

日ごとの推移（`daily`）が**どの日から全部数えてあるか**。日の鍵（`YYYY-MM-DD`）で返す。
画面はこれより前の日を描かず、「これより前は一部しか読んでいません」と添える
（読むのは `public/js/usage-days.js` の `dayChartView`。null とキーが無いときは線を描かない）。

**なぜ要るか。** 横断は新しい順に上限（既定 30・最大 60 本）までしか開かないので、
左端の日は開かなかったログのぶんが抜けている。実測で同じ 11-18 が、30 本では 46.2M、60 本では 82.0M だった。
全部数えた日と同じ顔で並べると左が低く出て、右肩上がりに読める（0 と不明を混ぜることになる）。

**決め方: 数えなかったログのうち、いちばん新しい最終更新（mtime）の次の日から。**

- 会話ログは追記しか起きないので、1本の中の要求はどれもそのログの最終更新より前にある。
  **実測（2026-11-24）で 552 本すべて**、末尾にある最新の timestamp ≦ mtime だった（はみ出し 0 本）。
  だから数えなかったログは、最終更新の日より後には要求を1つも持っていない
- **最終更新のその日は含めない。** 同じ日の 0 時からの要求を持っているかもしれない（0 時ちょうどでも次の日から）
- **日は地方時で切る。** `daily` の行の鍵と同じで、組み方は `parse/usage.mjs` の `localDay` の1箇所だけ
  （2箇所で組むと、片方だけ直した日に境目と行の鍵が黙って1日ずれる）。次の日は「日付を1つ進めた 0 時」で出す
  （24時間を足すと、夏時間の切り替わる日に同じ日へ戻ることがある）

「数えなかった」に入れるのは**中身が分からないものだけ**。

| 入れる | 入れない |
|---|---|
| 上限で開かなかったもの | 要求0本で表から外したもの（日ごとに何も足さない） |
| 期間で外したもの（`?days=` は最終更新で選ぶだけで、日で切っていない） | モデルで外したもの（絞り込みの意味として外した） |
| 開きに行ったが読めなかったもの | |

だから判断（`scanFromOf`）は、表から外す**前**の読んだ結果（`read`）を受け取る。
絞ったあとから決めると、モデルで絞っただけで境目が新しい側にずれ、そろっている日を捨てる
（調査の段階で、画面側で `rows` の最古から推す案を採らなかったのはこのため）。

**読んだ最古の最終更新からは決めない。** 開かなかったログの最終更新は索引（`indexTranscripts`）が
もう stat して持っているので、**読みは1回も増えない。** 読んだ最古より前でも、開かなかった最新より後の日は
そろっているので、こちらのほうが描ける日が多く、しかも正しい。

**null（決められない）にするのは3つ。** 0 と不明を分ける。

- 数えたセッションが無い（描く日が無い。境目だけ返すと「全部読めて 0」に見える）
- 数えなかったログの最終更新が分からない（どの日に要求があるか言えない。`0` も不明として扱う）
- 全部読めたのに、時刻の付いた要求が1本も無い（どの日にも置けない）

null にしないもの。

- **全部読めたとき**は `daily` の最初の日（欠けが無いので境目も無いが、null だと「決められない」と区別が付かない）
- **今日より後の日を返すことがある**（本数を少なく選んだ日に、今日動いたログまで読み切れなかったとき）。
  「そろっている日が1日も無い」は分かっている事実で、不明とは別物

判断は `usageResponse`（読んだあとの組み立て。ディスクを触らない）の中にあり、
`test/usage-view.test.mjs` が応答のキーの並びごと固定している。`listUsage` は
「どれを開くか」を決めて読み、`usageResponse` に渡すだけ。**`all` は期間で絞る前のものを渡す。**
`/api/usage` の合流（`server.mjs` の `coalesce`）は手を入れていない（同じ1回の読みの中で決まるため）。

クエリの読み取り（`intOf` / `textOf` / `getter` と、長さと期間の上限）は `view/query.mjs`。
`archive.mjs` と `usage.mjs` が**バイト単位で同じものを持っていた**ので寄せてある。
窓口を足すときもここから取る。**素の `Number()` で読まない**（`NaN` がそのまま下流へ流れる）。

書庫の置き場所の候補（`meta.projects`）は `buildProjects()` が作る。
**表示名は「グループごとに、いちばん新しい1本だけ末尾を読む」で取る。**
索引がタダで持っているのは `projectDir`（スラッグ）だけで、これは不可逆
（`C--…-claude-deck` の `-` は区切りかフォルダ名の一部かを区別できない）。
読むのは種類の数だけ（実測 445 本に対して 19 種）で `readTail` は memo に乗る。
候補は**絞り込む前の全行**から作る。期間で絞ったあとから作ると、
期間を変えるたびに候補が消えて選び直せなくなる。

`project` の照合は**完全一致を先に見て、当たらなければ部分一致へ落とす**。
画面は選ぶ形なので正確なスラッグが来るが、`?project=` を手で書くぶんも拾う。

**`view/` は `run/` を import しない。`run/` からも `view/` を import しない。**
起こしたセッションを一覧へ混ぜるのは `server.mjs` の `refresh()` の仕事で、
そこが合成の場所と決めてある。詳細は `src/run/CLAUDE.md`。

`src/view/summary.mjs` の `summarize()` が唯一の差し替え点。`detail.mjs` は結果の形しか見ていない。

**一度検討して、見送った（2026-09-06）。理由は費用。**
要約を AI に作らせると、セッションを開くたびに従量課金が発生する。
このアプリの他の機能は全部ローカルで完結していて、**開くだけで金が減るものが1つも無い。**
そこへ1つ混ぜると性質が変わる。技術的な障害があったわけではない（骨組みはそのまま貼れる）ので、
入り口は残してある。

差し替えるときは以下を守る（理由はファイル冒頭のコメントに詳しく書いてある）。

- 既定では通信しない。鍵が無ければ黙って素の要約に戻す
- ログ本文を外へ送る処理になるため、使うかどうかは利用者が環境変数などで明示的に選ぶ形にする
- 失敗しても詳細ビュー全体を落とさない
- 素の要約（`plainSummary`）を捨てない。AI 側が落ちたときの表示になる
