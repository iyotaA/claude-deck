# ClaudeDeck

並行して動かしている Claude Code のセッションを、一覧と詳細で見るツールです。

セッションを行き来していると、どれが自分の返事を待っているのか分からなくなります。
そして自分が何を答えたのかも思い出せません。

その2つを1画面で分かるようにしたものです。

## できること

- いま動いているセッションを一覧で出す
- どれが自分の返事待ちなのかを色で分ける
- 自分が選んだ選択肢と、その選択肢の説明を時系列で読み返せる
- 提出したプラン、却下したツール、使ったスキルも同じ時系列に並ぶ
- 文脈が圧縮された地点を出す。そこより前は Claude 側も覚えていません
- 何にトークンを使ったかを出す。どのツールが文脈を食っているかも見られます
- 画面から新しいセッションを起こして、そのまま会話を続けられる
- 途中でモデルや考える量を替えて、同じセッションの続きを起こし直せる
- 選んだセッションのターミナルを前面に出す
- 返事待ちに入ったことを Slack へ知らせる（設定したときだけ）
- その通知の設定を、画面の「設定」ボタンから変える。再起動は要りません
- 新しい版が出たら画面で知らせる。ボタン1つで入れ替わります

## 入れ方

次のページから `ClaudeDeckApp-win-Setup.exe` を落として、ダブルクリックしてください。

<https://github.com/iyotaA/claude-deck/releases/latest>

置き場所は聞かれません。
自分のユーザーフォルダーの中に入るので、管理者権限も要りません。

初回だけ、青い画面で止められることがあります。
署名を買っていないためです。
「詳細情報」を押してから「実行」を押すと進みます。

入れ終わると、そのまま画面が開きます。
次からはスタートメニューの ClaudeDeck から起動できます。

**Node.js は要りません。** 中に入れてあります。

### 入るもの

| 場所 | 中身 | 消えるとき |
|---|---|---|
| `%LOCALAPPDATA%\ClaudeDeckApp\` | アプリ本体 | アンインストールで消えます |
| `%LOCALAPPDATA%\ClaudeDeck\` | 設定・記録 | 消えません |

分けてあるので、アンインストールしても Slack の設定は残ります。
入れ直したときに、また設定しなくて済みます。

## 使い方

スタートメニューの ClaudeDeck から起動します。

専用の窓が開いて一覧が出ます。
アドレス欄もタブも無い、アプリらしい見た目です。

ポートを変えたいときは、環境変数 `CLAUDE_DECK_PORT` を指定してください。
埋まっている場合は自動でずらします。

すでに起動しているときにもう一度押しても、二重には立ち上がりません。
動いているほうの窓が前に出ます。

## PC を立ち上げたときに自動で動かす

**設定は要りません。** 入れた時点で登録が済んでいます。

次のログオンから、サーバーが裏で立ち上がります。
窓は出ません。見たいときにスタートメニューから開きます。

いまの状態は、画面の「設定」のいちばん下で見られます。

裏で動くぶん、画面に出ていた文字は次のファイルに残ります。

```
%LOCALAPPDATA%\ClaudeDeck\launcher.log
%LOCALAPPDATA%\ClaudeDeck\server.log
```

切り替えたいときは、次を実行してください。

```
"%LOCALAPPDATA%\ClaudeDeckApp\ClaudeDeck.exe" --uninstall-startup
"%LOCALAPPDATA%\ClaudeDeckApp\ClaudeDeck.exe" --install-startup
```

同じ実行ファイルに、他の操作もあります。

- `--status` … いまの状態をまとめて出す
- `--open` … 窓だけ開く
- `--stop` … 裏で動いているサーバーを止める
- `--background` … 窓を出さずに裏で立てる

### 前の方式から乗り換えるとき

フォルダーごとコピーして使っていた場合、スタートアップフォルダーにショートカットが残っています。

放っておくと古いほうも一緒に立ち上がり、2つのサーバーがポートを取り合います。
画面は出るのに設定が反映されない、という追いにくい形になります。

そこで、起動したときに自動で見つけて無効にします。
消さずに `ClaudeDeck.lnk.disabled` へ名前を変えるだけなので、戻すこともできます。

無効にしたときは、画面の「設定」に1行出ます。

## 新しい版に入れ替える

起動したときに、静かに確認しています。

新しい版があると、上のバーに帯が出ます。
「更新」を押すと、落として入れ替えて、勝手に起き直します。

窓は開いたままで構いません。
同じアドレスで戻ってくるので、そのまま使い続けられます。

途中で失敗したときは、その場で理由が出ます。
黙って元のままになることはありません。

いまの版は、上のバーの右のほうに出ています。
押すと確認の結果が読めます。

確認そのものを止めたいときは、環境変数を1つ立ててください。

```
setx CLAUDE_DECK_UPDATE_OFF 1
```

画面からは止められません。
自分で自分を締め出せる口は作らない、という決まりにしています。

## 席を外しているときに Slack へ知らせる

画面を見ていないと、セッションが止まったことに気づけません。
Slack へ飛ばしておけば、スマホで気づけます。

知らせるのは、あなたの返事で止まっている待ちだけです。
何が届くかは、あとの「何が届くか」にまとめてあります。

同じ待ちで二度は鳴りません。
待ちに入ってからしばらく続いていたときだけ送ります。
目の前にいてすぐ答えたぶんは、ここで消えます。

どの待ちで鳴らすかは、あとから画面の「設定」で選べます。

### 1. Slack 側で受け口を作る

`docs/slack-webhook-setup.html` をブラウザで開いてください。
画面つきの手順書があります。

飛ばす先は自分専用のチャンネルか、自分への DM にしてください。
**質問文がそのまま流れます。** 共有チャンネルは避けます。

### 2. 受け取った URL を ClaudeDeck に渡す

いちばん簡単なのは画面から入れる方法です。

上のバーの「設定」を押して、いちばん上の欄に URL を貼り、「保存」を押します。
再起動は要りません。その場で効きます。

保存した値は次の場所に入ります。

```
%LOCALAPPDATA%\ClaudeDeck\config.json
```

このファイルを直接書いてもかまいません。

```json
{
  "notify": {
    "slackWebhookUrl": "https://hooks.slack.com/services/...",
    "settleSec": 6,
    "idleMin": 2,
    "remindMin": 0,
    "detail": "full"
  }
}
```

手で書いた場合だけは、あとで ClaudeDeck を起動し直してください。
ファイルの見張りはしていないためです。

環境変数でも渡せます。

```
setx CLAUDE_DECK_SLACK_WEBHOOK "https://hooks.slack.com/services/..."
```

こちらは、画面でまだ設定していないときの初期値という扱いです。
画面から保存すると、そちらが勝ちます。

環境変数を入れたあとも起動し直しが要ります。
自動起動を使っている場合は `-Action stop` してから `-Action start` します。
ターミナルで `set` しただけの値は、裏で動いているサーバーには届きません。

### 3. 効いているか確かめる

いちばん早いのは「設定」の中の「テスト送信」です。
押すとその場で1通届きます。2分待つ必要はありません。

起動したときの黒い窓にも、1行増えていれば効いています。

```
ClaudeDeck
  http://127.0.0.1:4317/
  読み取り元: C:\Users\<あなた>\.claude
  Slack 通知: 有効（環境変数 / https://hooks.slack.com/services/T0AB…/B12…/****）
```

黒い窓が出ない自動起動のときは、次で見られます。

```
curl http://127.0.0.1:4317/api/health
```

`notify.enabled` が `true` なら効いています。
送った数・失敗した数・最後の失敗の理由も、ここに出ます。

URL は伏せた形でしか出しません。
そのまま人に見せても問題ありません。

### 変えられるところ

全部「設定」の中にあります。保存すればその場で効きます。

| 設定の名前 | 設定ファイル | 環境変数 | 既定 | 意味 |
|---|---|---|---|---|
| Slack Webhook URL | `slackWebhookUrl` | `CLAUDE_DECK_SLACK_WEBHOOK` | なし | これが入っているときだけ動きます |
| 落ち着き待ち | `settleSec` | `CLAUDE_DECK_NOTIFY_SETTLE` | 6 | 待ちに入ってから送るまでの秒数。0 ですぐ送る |
| 返信待ち | `idleMin` | `CLAUDE_DECK_NOTIFY_IDLE` | 2 | 返信待ちで送るまでの分。0 で返信待ちを送りません |
| リマインド | `remindMin` | `CLAUDE_DECK_NOTIFY_REMIND` | 0 | 放っておいたときの念押し。分で入れる。0 で無効 |
| 質問文 | `detail` | `CLAUDE_DECK_NOTIFY_DETAIL` | full | 「載せない」にすると質問文を送りません |
| 通知する状態 | `states` | なし | 全部オン | どの待ちで鳴らすかを1つずつ選べます |

**同じ項目が両方にあるときは、画面で保存したほうが勝ちます。**
環境変数は、画面でまだ設定していないときの初期値という位置づけです。

環境変数も立っている場合は、画面にその旨が出ます。
どちらの値が使われているのか、迷わないようにするためです。

質問の中身を Slack に流したくないときは、質問文を「載せない」にしてください。
どのセッションが待っているかだけが届きます。

うるさいと感じたときは「返信待ち」の分を伸ばしてください。
5 にすれば、5分席を外したときだけ鳴ります。

0 にすると、ほぼすべての通知が止まります。
実際に鳴っているのは返信待ちの経路だけだからです（次を参照）。

### いったん全部止めたいとき

環境変数を1つ立てると、設定に関係なく止まります。

```
setx CLAUDE_DECK_NOTIFY_OFF 1
```

これだけは画面より強い扱いです。
値そのものは画面が勝ちますが、機能ごと止めるのは環境変数からできます。

止めているあいだは、画面の「設定」にもその旨が出ます。
戻すときは環境変数を消して、起動し直してください。

### 何が届くか

届くのは、次の4つの待ちです。
「設定」の「通知する状態」で、1つずつ切ることもできます。

- 返信待ち … Claude が喋り終えて静かになった状態。2分たっても返事がなければ送ります
- 質問待ち … Claude が選択肢を出して止まっている状態
- プラン承認待ち … プランの承認を待っている状態
- 承認待ち … コマンドの実行許可を待って止まっている状態

**ほとんどの通知は「返信待ち」として届きます。**

Claude Code は質問を出しているあいだ、その質問をログに書きません。
書かれるのは答えたあとです。
そのため ClaudeDeck からは、質問中も「喋り終えて静か」に見えます。

実際に困る場面（席を外している間に止まっている）は、どちらでも同じように拾えます。
届いたときの見出しが「返信待ち」になる、というだけの違いです。

承認待ちについては、Claude が自分で判断して進めた分は送りません。
あなたに聞きに来て止まっているものだけが届きます。

### うまく飛ばないとき

まず「設定」を開いてください。いまの状態と、送った数・失敗した数が上に出ます。
止まっている場合は、その理由もそこに出ます。

- 環境変数 `CLAUDE_DECK_NOTIFY_OFF` が立っていると、何を設定しても鳴りません
- URL が `https://hooks.slack.com/` で始まっていないと、動きません。別のあて先へ業務内容を送る事故を防ぐためです
- URL が消されていた場合は、1回試して止まります。理由は `/api/health` に出ます
- 会社のプロキシを通さないと外へ出られない環境では届きません。追加のパッケージを使わない作りのため、対応できていません
- ClaudeDeck が動いていなかった間に始まった待ちは、飛びません。起動した直後に見えていた待ちも、飛ばしません。毎朝ログオンのたびに昨夜ぶんが全部鳴るのを防ぐためです

### Webhook の URL の扱い

**この URL は鍵そのものです。**
持っている人は誰でも、あなたのチャンネルに書き込めます。

Claude との会話に貼らないでください。
貼ると会話ログに残り、消しても残り続けます。
画面の「設定」か、環境変数か、設定ファイルに直接入れてください。

いちど入れた URL は、画面には出てきません。
出るのは `T0AB…/B12…/****` のように伏せた形だけです。
そのまま人に画面を見せても問題ありません。

## 一覧の見方

左に並ぶ色は、いまボールがどちらにあるかを表します。

- 赤 … あなたの番。質問待ち・プラン承認待ち・承認待ちのどれか
- 黄 … あなたの番。返信待ち。Claude は応答を返し終えています
- 青 … Claude の番。実行中
- 灰 … 終了。直近24時間のものだけ残ります

赤が並んでいたら、上から手をつければよい並び順になっています。

## 詳細の見方

一覧の行をクリックすると右側に出ます。

いちばん上に、このセッションを始めたときの指示が出ます。
「なんでこれをやっていたか」を思い出すための場所です。

その下の「あなたが決めたこと」に、質問と選んだラベル、その選択肢の説明が並びます。
選ばなかった案も畳んであるので、開けば比較できます。

時系列は「判断だけ」で絞り込めます。
Claude の説明が消えて、自分が動かした場面だけが残ります。

## 画面からセッションを起こす

上のバーの「起こす」を押すと、その場で新しいセッションを始められます。
ターミナルを開かなくても、この画面の中だけで会話が進みます。

書くのは最初の指示と、始めるフォルダーの2つだけです。
モデルや上限は、決めたいときだけ触ってください。

起こしたセッションは、いつもの一覧と詳細にそのまま並びます。
記録の残り方も、ターミナルで動かしたものと同じです。

### 確認はこの画面に出ます

ここから起こしたセッションも、作業の途中で聞きに来ます。
ターミナルで出る「これを実行していいですか」は、詳細の「あなたの番」に出ます。

**答えるまで待ちます。** 放っておくと、そこで止まったままになります。
10分たっても答えが無いときは断ったことにして、次の指示を待つ形に落ちます。

選択式の質問も同じ場所に出ます。札を選んで「この内容で回答する」で送ります。
どれも当てはまらないときは「その他（自分で書く）」に書けます。

既定は plan モードです。読んで考えるだけなので、ファイルは書き換わりません。
プランが出たら「あなたの番」に承認のボタンが3つ出ます。
**押したボタンで、そのあとの権限モードまで決まります。**

| 押すもの | そのあと |
|---|---|
| Yes（auto） | Claude が判断して、危ないものだけ確認に来ます |
| Yes, auto-accept edits | ファイルの変更まで自動で通します |
| No（プランを直す） | 承認せず、理由を書いて差し戻します |

「承認したのにファイルが書けない」が起きないように、承認とモードの移動を1つのボタンに束ねてあります。

### 始められるフォルダーは決まっています

どこでも起こせるわけではありません。
選べるのは、そのPCで Claude Code が動いたことのあるフォルダーだけです。

足したいときは、環境変数 `CLAUDE_DECK_RUN_DIRS` にパスを書いてください。
複数あるときは `;` で区切ります。

ボタン1つでコードが動く機能なので、届く先を先に狭めてあります。

### かかるお金

起こしたセッションは、ターミナルで動かしたときと同じだけ使います。
押し間違いに備えて、既定で 5 USD の上限を掛けてあります。

上限に達すると、そこで止まります。
フォームの「上限」で 0.01 から 50 まで変えられます。

何にトークンを使ったかは、詳細の「数値」で後から見られます。

### 続ける・止める・替える

起こしたあとは、実行パネルの下の欄から次の指示を送れます。
Enter は改行で、送るのは Ctrl+Enter です。

「止める」は2回押しです。
1回目で見た目が変わり、もう1度押すと止まります。

いま走っている手だけをやめさせたいときは「割り込む」です。**こちらは1回押しで効きます。**
会話は生きたまま残るので、そのまま次の指示を打てます（ターミナルの Esc と同じ働きです）。
使える claude かどうかは向こうが名乗るので、**対応していない版では札そのものが出ません。**

入力欄の上の「/ コマンド」から、`/context` のようなスラッシュコマンドを選べます。
選ぶと入力欄の頭に入るだけで、**送られはしません。** 中身を見てから自分で送ってください。

入力欄のすぐ上に「いま plan mode / opus-5」のような札が出ています。
そこを押すと窓が開いて、権限モード・モデル・思考量・上限を選び直せます。
モデルは使ったことのあるものが並びます（そこに無い名前は「自分で入力」から渡せます）。

走っている最中に権限モードとモデルだけを替えたときは、**そのまま動いているものに効きます。**
止めも建て直しもしないので、いま進んでいる作業は続きます。
替えたことが向こうに届くまでの一瞬だけ「替えています…」と出ます。

思考量や予算も一緒に替えたとき、あるいは1往復を終えて止まっているときは、
いまの分を畳んでから、同じセッションの続きを起こし直します。

どちらの道でもセッションの ID は変わりません。
一覧も詳細も、開いていたリンクもそのまま使えます。

### 止まらないときの止め方

この画面から起こしたセッションは、ClaudeDeck の子として動きます。
ClaudeDeck を終了すれば、抱えている分もまとめて落とします。

それでも残ってしまったときは、実行パネルに出ている PID を使ってください。

```
taskkill /PID <PID> /T /F
```

会話の記録は Claude Code 自身が残しています。
途中で止めても、そこまでの分は一覧と詳細から読めます。

## 窓が狭いときの一覧

窓の幅が狭いと、一覧は左上のボタンの中にしまわれます。

押すと一覧が手前に出てきます。
セッションを選ぶと自分で閉じて、詳細が画面いっぱいに戻ります。

閉じ方は4つあります。
- 左上のボタンをもう一度押す
- 一覧の右上の × を押す
- 背後の暗いところを押す
- Esc キーを押す

## ターミナルを前面に出す

詳細の「ターミナルを前面に」を押すと、そのセッションの窓が前に出ます。

タブで複数セッションを開いている場合、窓は前に出ますがタブは選べません。
タブの切り替えだけ手動でお願いします。

すでにターミナルで動いているセッションへは、画面から指示を送れません。
動いている窓に文字を打ち込む仕組みが、公開されていないためです。
無理に真似ると、バージョンが変わったときに黙って壊れます。

続きを自分で打つために「再開コマンドをコピー」を用意しています。

新しく始めてよければ、画面から起こすほうが早いです。
そちらは公開されている入口を使うので、この心配がありません。
やり方は「画面からセッションを起こす」にあります。

## ターミナルだけで見る

窓を開かずに一覧だけ見たいときは、こちらを使ってください。

```
node cli.mjs          一覧を1回出す
node cli.mjs --live   3秒ごとに出し直す
node cli.mjs --all    終了したものも全部出す
```

インストールして使っている場合、`node` は同梱のものを指します。

```
set DECK=%LOCALAPPDATA%\ClaudeDeckApp\current
"%DECK%\runtime\node.exe" "%DECK%\app\cli.mjs"
```

## 読んでいるもの

`~/.claude` の下にある、Claude Code が自分で書いているファイルです。

- `sessions/<PID>.json` … 動いているセッションの登録簿
- `projects/<スラッグ>/<セッションID>.jsonl` … 会話ログ
- `tasks/<セッションID>/` … TODO の状態

`CLAUDE_CONFIG_DIR` が設定されている場合は、そちらを読みます。

**書き込みは一切しません。** 読み取り専用です。

## 使っている技術

本体は Node.js とブラウザの標準機能だけで動きます。
**外部パッケージは1つも使っていません。**

| 層 | 使っているもの |
|---|---|
| サーバー | Node.js 18 以降・`node:http`（静的配信・JSON API・SSE） |
| 読み取り | `node:fs` / `node:fs/promises`（`fs.watch` ＋ 2秒ポーリング） |
| 更新の push | SSE（画面側は `EventSource`） |
| セッション実行 | `node:child_process`（claude CLI を裏で起こす） |
| 外へ出る通信 | Slack への POST だけ（`fetch`。設定したときだけ） |
| 画面 | バニラ JS 31 枚（ESM）・素の CSS 11 枚 |
| テスト | `node:test` ＋ `node:assert/strict`（29 ファイル） |
| Windows | PowerShell 4 枚・`.cmd` 1 枚 |
| 依存 | なし（`dependencies` は空） |

ビルド工程はありません。
保存して画面を読み込み直せば反映されます。

PowerShell の4枚は Windows 側の細かい仕事に使っています。

- `focus.ps1` … `user32.dll` でターミナルの窓を前面に出す
- `build-icons.ps1` … `System.Drawing` で favicon を作る
- `autostart.ps1` … 前の方式の自動起動。フォルダごとコピーで使う人向けに残しています
- `release.ps1` … 配布物を組み立てて GitHub へ上げる

### 窓とインストーラー（`launcher/`）

窓を出す部分と、更新を当てる部分だけは C# です。

| 使っているもの | 何のため |
|---|---|
| .NET 9（`win-x64`・単一ファイル・トリム済み） | Node.js が無いPCでも動かすため |
| Velopack | インストーラーと差分更新 |
| Edge のアプリモード | アドレス欄もタブも無い、専用の窓 |

**本体（`src/` と `public/`）は、これが有っても無くても同じように動きます。**
リポジトリを落として `node server.mjs` で起動すれば、C# は1行も通りません。

分けてある理由は2つあります。

Node 側の「外部パッケージを増やさない」という決まりを守るため。
そして、更新のときに Node 自身が入れ替わるためです。
自分を置き換える手続きを、自分の中に持たせたくありません。

## 気をつけること

会話ログには業務の内容が入ります。
そのため受け付けるのは `127.0.0.1` からだけにしています。
社内ネットからは見えません。

設定を書き換える口は、この画面から来た指示だけを受け付けます。
ブラウザで開いた別のページから設定を勝手に書き換えられないようにするためです。

この画面からはセッションを起こせます。
コードが実際に動くので、ほかの機能とは危なさの質が違います。

始められるフォルダーを、動いたことのある場所だけに絞ってあるのはそのためです。
許可を一切求めない権限モードは、環境変数を立てたときだけ選べます。

外へ出ていく通信は2つだけです。

1つは更新の確認で、GitHub のリリースページを見に行きます。
こちらから送るものはありません。
止めたいときは `CLAUDE_DECK_UPDATE_OFF=1` を立ててください。

もう1つは Slack への通知で、設定したときだけ `hooks.slack.com` へ送ります。
そこへ流れるのは、セッション名・プロジェクト名・状態・質問文です。
質問文を流したくないときは `detail` を `none` にしてください。

読んでいるのは Claude Code の内部データで、公開された仕様ではありません。
バージョンが上がると形が変わることがあります。
知らない形が来ても止まらないようには作ってありますが、
表示が減ることはあります。

## 同僚に渡すとき

リリースのページを教えるのがいちばん簡単です。

<https://github.com/iyotaA/claude-deck/releases/latest>

以後は本人が新しい版を取りに行けます。
社内のどこかに `ClaudeDeckApp-win-Setup.exe` を置いて配っても構いません。

**Node.js も、管理者権限も、設定ファイルの用意も要りません。**

初回だけ青い画面で止まることは、先に伝えておくと親切です。
「詳細情報」→「実行」で進みます。

Slack の通知は、渡した先では無効のままです。
使いたい人が、自分の Webhook を自分で入れることになります。
画面の「設定」から貼るだけなので、`setx` の説明は要りません。

**あなたの URL が一緒に渡ることはありません。**
設定は配布物の外（`%LOCALAPPDATA%\ClaudeDeck\`）に置いてあるためです。

## 自分で配布物を作るとき

作るのに要るものは3つです。

- .NET SDK 9 以降
- `dotnet tool install -g vpk`（Velopack のコマンド）
- gh CLI（認証済み。上げるときだけ）

`package.json` の `version` を上げてから、次を実行します。

```
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Action all
```

**版の出どころは `package.json` の1箇所だけです。**
C# 側にも `vpk` にも、版を書き写しません。

途中で止めたいときは `-Action` を分けて呼べます。

- `fetch-node` … Node.js を公式から落とす（SHA256 で中身を確かめます）
- `stage` … 配布物を組み立てる
- `pack` … インストーラーを作る
- `upload` … GitHub へ上げる

出来上がりは `build\releases\` に落ちます。

`scripts/` の中の `.ps1` は UTF-8 BOM 付きで保存されています。
BOM を外すと、古い PowerShell で読めなくなります。編集するときは気をつけてください。

## リポジトリから動かすとき

直すときや、中を見たいときの動かし方です。

```
git clone https://github.com/iyotaA/claude-deck
cd claude-deck
node server.mjs
```

Node.js 18 以降が要ります。
`npm install` は要りません。外部パッケージを使っていないためです。

この動かし方では、更新のボタンは押しても断られます。
自分で `git pull` するほうが確実なので、そう答えるようにしています。

インストール版と同時に動かすと、ポートを取り合います。
先に `set CLAUDE_DECK_PORT=4318` のように逃がしてください。

## アイコンを差し替えるとき

タブに出るアイコンは `assets/favicon.png` から作っています。

絵を差し替えたら、次を実行すると作り直せます。

```
powershell -ExecutionPolicy Bypass -File scripts\build-icons.ps1
```

`public/favicon.ico`（16 / 32 / 48 px）と `public/favicon-192.png` ができます。
まわりの透明な余白と影は自動で切り落とすので、元絵はそのまま渡してかまいません。
